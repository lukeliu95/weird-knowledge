# 读者：摘录、溯源与思考框架 方案

> v0.2 · 2026-10-18 · 状态：Luke 已确认，已搭好骨架

## 1. 要做成什么

把在 X 上看到的好内容存下来。攒多了以后做三件事：

1. 给每条新知识找到它背后的**源知识**，也就是底层的理论、方法论、论文、研究报告
2. 统计哪些源知识被反复指向。被指向得越多，越接近本质
3. 提炼成 Luke 自己的**思考框架**：几条他相信的原则，每条都能指回出处

一句话：新知识是叶子，源知识是根，框架是 Luke 自己长出来的树。

## 2. 已经定下的选择

| 问题 | 选择 |
|---|---|
| 存在哪里 | 项目文件夹里的 md 文件。Claude 的记忆里只留一行指针 |

## 3. 三层结构

```
① 新知识  clips/        你看到的推文、文章（原文不改）
      │  整理时溯源
      ▼
② 源知识  roots/        理论、方法论、论文、研究报告（一个理论一个文件）
      │  源知识之间也会往上连，一直追到公认的基础理论
      ▼
③ 思考框架 framework.md  你的原则 + 你的知识底座（被最多新知识指向的源理论）
```

| 层 | 存什么 | 谁来写 |
|---|---|---|
| 新知识 | 原文、作者、链接、日期、你的一句"为什么存"，以及整理后补上的溯源结果 | 原文照抄；溯源由我写在原文下面 |
| 源知识 | 理论名、提出者、年份、一句话核心主张、原始出处链接、更底层的源头、有哪些新知识指向它 | 我写，必须联网核实 |
| 思考框架 | 原则、支撑它的新知识和源知识、矛盾、没想清楚的问题 | 我起草，你定稿 |

## 4. 目录

```
读者/
├── AGENTS.md          项目规则：怎么存、怎么溯源、怎么整理（Claude 和 Codex 共用）
├── CLAUDE.md          只有一行：以 AGENTS.md 为准
├── clips/             ① 新知识，一条一个文件，例如 2026-10-18-author-short-title.md
├── roots/             ② 源知识，一个理论一个文件，例如 galls-law.md
├── framework.md       ③ 思考框架
└── docs/
    ├── 2026-10-18-plan.md          本方案
    └── reviews/                    每轮整理的记录，例如 2026-10-25-round-1.md
```

## 5. 存一条时做什么

1. 拿到原文：你贴原文，或者给链接由我用 `opencli` 抓。抓不到就请你贴
2. 写进 `clips/`，带上作者、链接、保存日期、你的"为什么存"。原文保持原语言，一字不改
3. 只做一个轻标记：它可能和框架里的哪条原则有关
4. 数一下没整理的条数，到 10 条时提醒你

## 6. 整理时做什么（核心）

**对每条没整理的新知识：**

1. **剥包装**：用一句话写出它的核心主张，去掉案例、修辞和情绪
2. **找源头**：联网查这个主张和哪些已知的理论、方法论、论文、研究报告相同或相近
3. **判关系**：按下表归类
4. **往上追**：源知识本身还有没有更底层的源头？一般追 2 到 3 层，追到公认的基础理论为止（比如反馈控制、演化与选择、激励、信息论这一层）
5. **写本质**：一句话写清"这条新知识本质上是 X 理论在 Y 场景下的应用"

| 关系 | 意思 | 对你有什么用 |
|---|---|---|
| 直接源自 | 作者明说了，或者明显就是在用这个理论 | 看懂它从哪里来 |
| 换了说法 | 本质就是老理论，只是换了新名词 | 识别"旧瓶装新酒"，省时间 |
| 相近 | 作者自己想出来的，但和某个理论很像 | 两边可以互相印证 |
| 挑战 | 和经典理论的说法相反 | 最值得注意：要么是真的新东西，要么是错的 |
| 没找到源头 | 查不到相近的已知理论 | 可能是真的新知识，标"待查" |

**全部查完后汇总：**

6. 更新 `framework.md`
7. 在 `docs/reviews/` 写本轮记录：查了哪几条，新增了哪些源知识，框架改了什么

做法：每条新知识派一个 subagent 并行去查，主会话负责汇总和判断。

## 7. framework.md 的样子

**第一部分：我的原则**

每条原则写清这几项：

| 项 | 说明 |
|---|---|
| 原则 | 一句话 |
| 支撑的新知识 | 几条，分别链接到 clips/ |
| 对应的源知识 | 链接到 roots/ |
| 矛盾 | 有没有新知识或理论跟它对着干 |
| 没想清楚的问题 | 还需要什么证据 |
| 状态 | 草稿（我提炼的）/ 已确认（你认可的） |

**第二部分：知识底座**

按"被多少条新知识指向"给源理论排序。排在最前面的几个，就是你最近看到的这些新东西共同的根。

**第三部分：待查**

没找到源头的想法，以及和经典理论对着干的想法，单独列出来，这里最可能藏着真正的新东西。

## 8. 防止编造的规矩

- 每条源知识都必须联网查到原始出处（论文、书、作者本人的文章），并附上链接。只凭我的记忆不算数
- "谁最先提出"有争议时，写明有争议
- 关联强弱分两档：强（有明确证据）、弱（我的推断）。弱关联标"待你确认"
- 原文一字不改，溯源写在原文下面
- 框架里的原则，我写的都算草稿，你确认后才改成"已确认"

| 你的原则 | 源知识 | 更底层 | 关系 |
|---|---|---|---|
| 先骨架后填充 | 盖尔定律（John Gall，1975，《Systemantics》）：能运作的复杂系统，都是从能运作的简单系统演化来的。精益创业里的 MVP（Eric Ries，2011）也是同一个意思 | 复杂系统的渐进演化（待核实） | 换了说法 |
