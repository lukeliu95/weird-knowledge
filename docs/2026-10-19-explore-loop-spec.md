# 探索循环：lukee 自己上网，顺着 Luke 的兴趣往外学

> 2026-10-19 · Luke 选了方案 B（每小时一轮、每轮 3 个侦察兵、每天 2 份日报），说"不用担心费用，尽管学"。规则写进 AGENTS.md v1.8「流程六」
> 起因：Luke 要 lukee 不停地上网学习，按自我进化的理论学他的兴趣，在全网展开；要有循环，或者派几个 subagent 去收集
> 关系：这是第六件事「探索」。补课（流程四）是补框架里薄的地方，探索是顺着 Luke 已有的兴趣往外扩；两者都由 Luke 定稿

## 一、先说结论

| 问题 | 回答 |
|---|---|
| 怎么做到"不停" | 用桌面端的定时任务，每 2 小时自动开一轮。每轮是一个新会话，进度全存在文件里，聊天窗口关了也照样跑 |
| 派谁去找 | 4 种"侦察兵" subagent，各管一类来源：X、论文、技术社区、日文网页。每轮按抽签派 2 个 |
| 往哪找 | 一张"兴趣地图"，十几个方向，每个方向记着"找回来的东西 Luke 想不想看"。想看得多的多去；新方向也固定留名额 |
| 学到的东西怎么回到 Luke 身上 | 每天早上推一份 10 条的日报，Luke 回字母说想看哪几条，大约 1 分钟。想看的存进库里，回答同时变成训练 lukee 的标签 |
| 怎么证明它在进化 | 看日报的命中率能不能超过 X 首页推荐给 Luke 的内容，并且一周比一周高。改动照流程五的规矩：比现状好的概率到 80% 才留 |

**最关键的一个判断：找资料已经很便宜，瓶颈是 Luke 的判断。** 侦察兵一天能翻几百条，但没有 Luke 说"想看 / 不想看"，lukee 不知道自己找得对不对，转得再快也是原地打转。所以这套循环的设计目标是：**用 Luke 最少的时间，换最多的判断信号**。这是原则 3（变便宜的旁边才稀缺）和原则 6（执行变快后，瓶颈移到验收）在这里的应用。

## 四、整体结构

一轮循环分五步。确定的事交给脚本，要判断的事交给模型。

| 步 | 谁做 | 做什么 |
|---|---|---|
| 1. 选 | 脚本 | 从兴趣地图抽签选 2 个方向：一个已知的强兴趣（往深挖），一个相邻的新方向（往外扩）。再抽签给每个方向配一种侦察兵 |
| 2. 找 | 2 个侦察兵 subagent | 各带一个方向、一类来源，交回 10～20 条候选：原链接、一句话说是什么、为什么可能对 Luke 有用、相邻的新线索（提到的理论、作者、项目） |
| 3. 筛 | 脚本 + Jev + 本地 Qwen | 去重（和 `clips/`、候选池比）→ Jev 分 kind 和 topic → 本地 Qwen 用冠军配置打"Luke 想不想看"的概率 → 进候选池 |
| 4. 给 | 每天早上 8 点那一轮 | 从候选池挑 10 条做日报，推到手机：6 条最可能想看、2 条最拿不准、2 条新方向（顺序打乱） |
| 5. 学 | Luke 回答后 | 想看的存进 `clips/`（走流程一）；回答写进标签库；兴趣地图和侦察兵各自记一笔命中或没命中；新方向命中 3 次以上，提给补课当题目候选 |

### 兴趣地图

- 初始十几个方向，来自三处：主题地图里 Luke 看得多的主题、知识底座里被指向最多的源知识、Luke 亲口确认过的偏好
- 每个方向记"展示过几条、Luke 想看几条"，抽签按这个算（Thompson 抽样）

### 什么时候自己降速（防止空转）

- Luke 连续 2 份日报没答：停派侦察兵，只跑本地；他一答就恢复
- 候选池里没展示过的超过 500 条：先停找，等消化
- 订阅用量撞到上限：存好状态，这一轮结束，下一轮再看

## 八、风险

| 风险 | 怎么防 |
|---|---|
| 空转：没有新信号还一直跑 | 挂在 Luke 的回答上，没回答就降速（见第四节） |
| 越推越窄（回音室） | 固定 2 条新方向、2 条拿不准，不全按预测分 |
| X 限流或账号被风控 | 每轮最多 1 个 X 侦察兵，留间隔、缓存；只读，不发、不点赞、不关注 |

## 十一、下一步：帮 Luke 做决定，给别的 agent 用

Luke 2026-10-19 说：要越来越像他，能帮他做决定，这样别的 agent 可以引用 lukee、请它协助。

**客户是谁**：Luke 的其他 agent（工作分身、各项目里的 Claude Code 和 Codex）。它们现在遇到"该选 A 还是 B"只能停下来问 Luke，Luke 成了所有 agent 共同的瓶颈（原则 6）。lukee 能先给一个"Luke 多半会选什么、有多确定、依据是什么"，它们就能少停、少问。

**怎么做（草稿）**

| 部分 | 做法 |
|---|---|
| 接口 | 一个命令：别的 agent 把问题、选项、背景交给它，拿回"多半选哪个、概率、依据（哪条已确认的原则、哪次相似的选择）、这件事要不要必须交给 Luke" |
| 判断引擎 | 本地 Qwen（私人资料不出这台机器），档案加相似的历史选择做例子（流程五证明"给例子"比"写规则"好） |
| 测试集（流程五里的 L3） | Luke 过去在会话里对 A / B / C 的真实回答。按时间切：老的做例子，新的做考题 |
| 放权 | 按原则 12 分级：碰钱、对外发送、删除、难撤销的，永远只给建议、必须交 Luke；其余先只给参考意见，考题一致率达标、Luke 抽查没出错，再一级级放宽 |

**要 Luke 同意的一件事**：测试集要从他过去的会话记录里取他做过的选择。方案 2026-10-18 写过"会话记录要他同意才读"。读的范围（这台 Mac 上的 Claude Code 和 Codex 会话），只抽"lukee 给选项、Luke 回答"的那几句，存进 `private/`，只交给本地 Qwen 和主会话用，不进公开仓库。
