# 做事方法的经验库

> 记录补课、整理、存这些流程里"什么做法起了作用、踩了什么坑"。下次派 subagent 或写脚本前先读这里。做法见 [自我优化 spec](2026-10-18-self-evolution-spec.md) 第 18 条（借自 Harness² 的改进经验库）。
> 只记有过一次以上实际证据的；不涉及 Luke 的私人信息。

| 日期 | 环节 | 经验 | 证据 |
|---|---|---|---|
| 10-18 | 查资料 | 派 subagent 联网时，把"不把 Luke 的个人信息写进外部请求"原样写进任务说明 | 第 1 轮有 4 个 subagent 把邮箱带进了外部请求（AGENTS.md v1.1） |
| 10-19 | 核实出处 | DOI 一律到 Crossref 按标题搜，不凭记忆写 | 凭记忆写的西蒙 1946 的 DOI，查出来是 Dahl 1947 的另一篇 |
| 10-19 | 抓推文 | X 的作者推文接口每轮只能抓约 5 位作者；改用搜索接口（`from:作者 since:日期`）并按作者缓存，被限流就停，下轮接着抓 | 回顾式测试集两次被 429 打断 |
| 10-19 | 读论文 | arXiv 的 HTML 转文字时，公式里的数字会丢，要读 `<math>` 的 alttext | Harness² 摘要里的"最多提升 X 分"读出来是空的 |
| 10-19 | 读文件 | 推文里有 U+2028 等特殊换行符，jsonl 不能用 splitlines 读，要按 `\n` 切 | 时间线快照读取报 JSON 解析错误 |
| 10-19 | 读论文 | 本机没有 pdftoppm，Read 读不了 PDF；优先找 HTML 版，或用 python 抽文字 | Harness² 的 PDF 读取失败 |
| 10-19 | 链接核查 | 抽链接时要处理带括号的维基链接、全角括号、`Jr.` 结尾、撇号，中文链接要转码 | 第一次核查报了 59 个失效，大部分是脚本误判 |
| 10-19 | 补课 | 先 grep 仓库有没有同一篇；另一个会话可能刚存过 | Taylor 1968 在补课前已被另一个会话存过 |
| 10-19 | 浏览器 | subagent 在内置浏览器打开出版社 PDF 链接会触发下载弹窗，任务说明里要写"PDF 用 curl 下载，不用浏览器打开" | 第 1 题和第 4 题各发生一次 |
| 10-19 | 补课 | 学术机构库（如 Syracuse）用 curl 和 WebFetch 会被拒，要用浏览器打开；这类分题会比别的慢很多（这次用了 2 个多小时），派任务时要预留时间 | 补课第 4 题分题 1 |
| 10-19 | 补课 | 多个 subagent 会各自提议同一个源知识的不同 slug（如 Taylor 1968 被提成两个名字），主会话合并时要先对齐命名 | 补课第 4 题 |
| 10-19 | 核实出处 | 有的期刊 DOI 在 DataCite 注册，Crossref 按标题搜不到期刊版（只搜到 SSRN 预印本）；这时用 doi.org 解析核实，不要当成查不到 | 补课第 9 题，Survey Research Methods 的 Gaul 等 2025 |
| 10-19 | 读网页 | Gartner 新闻稿、中小企業庁网站对 WebFetch 和脚本返回 403；Gartner 用内置浏览器能读，中小企業庁要另找同内容的 PDF 或换材料 | 补课第 9 题分题 B、C |
| 10-19 | 合并溯源 | 补课用 `tools/merge_trace.py` 时它会写“（第 N 轮）”，要再换成“（补课第 N 题）”；派 subagent 时按 COMMON.md 的统一格式交结果，主会话用脚本一次生成新知识文件，比手写 15 个文件快且不漏字段 | 补课第 9 题 |
| 10-19 | 探索 | X 搜索接口一轮做到第 4 次就会 429；每轮最多 4 次、间隔 20 秒，先搜最有把握的词。"digital twin" 这类泛词搜出来多是工业和币圈广告，要加限定词 | 探索第一轮 X 侦察兵 |
| 10-19 | 探索 | Semantic Scholar 接口连续 429（6 次只过 1 次），论文侦察兵改用 OpenAlex；arXiv 关键词搜索噪音大，看 econ.GN 这类分类的最新列表更准；SSRN、Wiley 对脚本返回 403 | 探索第一轮论文侦察兵 |
