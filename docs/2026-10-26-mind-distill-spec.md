# lukeeMind 补上"提炼"和"审过才用上"两步

> 2026-10-26 · Luke 选了 B · 代码：`tools/mind/distill.py`、`tools/mind/ask.py`

## 起因

Luke 给了一张客服系统常见的知识循环图：工单进来 → AI 写草稿 → 客服确认或修改 → 攒下处理经验 → 定时蒸馏成知识候选（筛选、脱敏、去重、提炼） → 人审过才发布 → 下次写草稿时用上。这个循环最值钱的地方，是客服改了什么。

拿 lukeeMind（流程七：当大脑）对照：

| 图里的步骤 | lukeeMind 原来 | 情况 |
|---|---|---|
| 1 新问题进来 | 别的 agent 用 `ask.py ask` 来问 | 有 |
| 2 写草稿 | 给出建议、把握、依据 | 有 |
| 3 人确认或修改 | Luke 回字母，多数时候还补一句话 | 有 |
| 4 攒经验 | `private/mind/asks.jsonl`、`private/l3/decisions.jsonl`、`corrections.jsonl` | 有 |
| 5 定时提炼 | 只有"想不想看"这边每周重写口味说明，"怎么拿主意"这边没有 | 缺一半 |
| 6 审过才用上 | 例子里只有旧题和他选的字母，他补的话没用上 | 缺 |

背后的道理：[知识获取瓶颈](../roots/knowledge-acquisition-bottleneck.md)（理论）：做专家系统最难的，是把专家脑子里的知识挖出来。这个循环的办法是不专门去挖，让专家在干活时顺手留下。

## 做法

| 步骤 | 做什么 | 谁来做 |
|---|---|---|
| 例子带原话 | `ask.py` 找相似旧选择当例子时，把 Luke 补的话也带上（开关 `NOTES_DEFAULT`） | 代码 |
| 做案例卡 | 三类事各做一张卡：Luke 补了话的、没按推荐选的、他说过"不对"的。卡上写要定什么、他选了什么、他的原话、能看出什么，人名和公司名换掉 | Opus，每周增量 |
| 写规律草稿 | 同一方向至少 3 张卡支持，才写成一条"遇到什么，他会怎么做"，并写明什么时候不适用。和 12 条原则、已确认的规律意思相同的不写，Luke 否掉过的不写 | Opus |
| 复核 | 另起一次判断，以挑错为主：引用的卡是不是真的支持、有没有反例、有没有说过头。真正支持的少于 3 张，或反例不比支持少，就删掉 | 本地 Qwen 开着就用它，连不上才用一次独立的 Opus |
| Luke 认 | 每周最多 3 条，没答完的不出新的 | Luke |
| 下次用上 | Luke 认过的规律进 `ask.py` 的提示词（开关 `RULES_DEFAULT`） | 代码 |

## 不照搬的两处

1. **人审会成为新的堵点。** 图里每条候选都要人审。我们吃过这个亏，一度攒了 882 处等 Luke 确认。所以先让另一个模型复核，Luke 只看最后的规律，每周最多 3 条。
2. **只审草稿，人会慢慢变成顺手点"同意"。** 背后的道理：[Endsley 1995 年的研究](../roots/endsley-1995-out-of-the-loop.md)（论文，实验）发现，自动化把人从动手的变成旁观的，人就会变被动。这次先不处理，留作选项 C：每周混几道不带推荐的题，看一致率是不是被抬高了。

## 回测（事先定好的判定标准，跑之前写下）

- 题目：`private/l3/decisions.jsonl` 里最近的 128 道旧选择题，和以前的回测一样，去掉推荐标记，每题只用更早的题做例子
- 规律按周模拟提炼：在 10-02、10-09、10-16、10-23 四个时点，各只用这个时点以前的案例卡写草稿、复核；每题只用它之前最近一次提炼出的规律，10-02 以前的题不带规律
- 对照：现状（不带原话、不带规律）跑 2 遍；B（带原话、带规律）跑 2 遍；另外"只带原话"跑 1 遍，只做诊断，不参与判定
- **判定：B 两遍平均猜中的题数不少于现状两遍的平均，就把 `NOTES_DEFAULT`、`RULES_DEFAULT` 都改成开**，否则保持关，代码留着
- 另外报这几项：高确定的题里猜中几道、Luke 没按推荐选的题、带了规律的题
- 偏乐观的地方：回测把复核通过的草稿都当成 Luke 认过了，实际他会否掉一些

## 成本

都走 Claude Code 订阅（`claude -p`），不另花钱。做卡：每 8 件一次调用，第一次约 19 次，之后每周只做新增的。提炼：每周写草稿 1 次、复核 1 次。回测：5 遍 × 128 次。
