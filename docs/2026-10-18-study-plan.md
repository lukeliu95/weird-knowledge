## 为什么要补课

前三件事（存、溯源、维护框架）只能顺着 Luke 已经看到的东西长。他没看到的那块，库里会一直空着。补课就是 agent 主动去找一手材料，把框架里薄的地方补上，做成简报让 Luke 学。

## 怎么做

| 项 | 定了什么 |
|---|---|
| 节奏 | 每周一题，由定时任务触发；Luke 说"补课"也做一题 |
| 题目从哪来 | 框架里每条原则下面"没想清楚的问题"、「待查」、主业相关但库里覆盖薄的方向 |
| 材料 | 每题 6～15 份一手材料。厂商调查要标出来，并写明这家卖什么 |
| 产出 | 每份材料存一条新知识并溯源，再写一份学习简报（md 存进 `docs/study/`，同时发成网页） |
| 谁定稿 | Luke 回答简报最后的问题，并说哪些材料"认"。认了的才进知识底座排名和主题地图 |
| 检验 | 能用真实数据验证的结论标"待验证"，下一题开始前问一次结果 |
| 成本 | 每题大约派 3 个 subagent，只花订阅里的用量，不调收费接口 |

没选的方案：B（只给书单，消化全靠 Luke）、C（全自动选题、存、改框架，违背"模型出草稿，人来定稿"）。
