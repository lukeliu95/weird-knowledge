# 规格驱动开发（Specification-driven development (spec-driven development)）

## 一句话

先写规格说明，再照规格开发：2004 年的版本把测试和契约都当作规格；2025 年的 AI 版本把 Markdown 规格当成唯一的事实来源，让编码 agent 按“规格→计划→任务→实现”生成和检查代码。

## 原始出处

- Specification-driven development，英文维基百科，https://en.wikipedia.org/wiki/Specification-driven_development
- Agile Specification-Driven Development, Ostroff, Makalsky & Paige, XP 2004, LNCS 3092, pp. 104–112, 2004，https://doi.org/10.1007/978-3-540-24853-8_12
- Spec-driven development with AI: Get started with a new open source toolkit, Den Delimarsky, GitHub Blog, 2025-09-02，https://github.blog/ai-and-ml/generative-ai/spec-driven-development-with-ai-get-started-with-a-new-open-source-toolkit/
- 争议：同一个名字有两层意思：2004 年 Ostroff 等人指“测试驱动开发 + 契约式设计”；2025 年 AI 编程语境下指“以 Markdown 规格为事实来源驱动 agent 生成代码”。后者并不是由某一个人首创，GitHub Spec Kit 是最常被引用的推广者。
