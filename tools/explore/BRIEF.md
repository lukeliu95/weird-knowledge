# 日报简介：读原文，给每条写简介

> 给"简介"subagent 的任务说明。主会话出完日报（`explore.py digest`）后派一个，任务说明 = 本文全文 + 那份日报的路径。
> 起因：Luke 2026-10-25 说日报每条只有一句话，看不出值不值得点开，要"相当于简介，内容再多一点"，好让他判断。
> v1.1 · 2026-10-25（v1.1：要点限字数）

## 你要做的

日报文件是 `private/explore/digests/<stamp>.json`，`items` 里有 10 条，每条有 `letter`、`url`、`title`、`author`、`source`、`published`、`what`（侦察兵写的一句话）。

对每一条：

1. **读原文**。按下面「怎么读」打开 `url`，读到能说清楚它讲了什么为止。论文读摘要、引言和结论，有数字表的看表
2. **写简介**，写进下面的 JSON

全部写完后，把 JSON 存到 `private/explore/digests/<stamp>.briefs.json`，回一句"写好了 N 条，没读到原文的是哪几条"。

## 每条写什么

| 字段 | 写什么 | 要求 |
|---|---|---|
| `title_zh` | 中文标题 | 原标题不是中文时写，10～25 字，说清楚讲什么，不做标题党；原标题是中文就写空字符串 |
| `intro` | 3～4 条要点，每条一句，不超过 50 字，合计不超过 200 字 | 第一条先说结论或最重要的发现；中间写怎么做的、关键数字、谁做的；最后一条写局限或要打折的地方（样本小、厂商自己的调查、只是宣布还没发布、转述等）。数字必须是原文里的。细节挑最能帮他判断的，不求全 |
| `for_you` | 和 Luke 的关系，一句，不超过 50 字 | 说这条碰到他的哪件事（见下面「Luke 在做什么」），只说有什么关系，不劝他看。没有明显关系就写"和你手上的事没有直接关系，属于 X 方向的新东西" |
| `length` | 原文篇幅 | 如"推文"、"串推 6 条"、"约 3000 字"、"论文 24 页"、"视频 12 分钟" |
| `read` | 读到原文没有 | 读到写 true。打不开（要登录、被删、403）写 false，这时 `intro` 只根据日报里的 `what` 和标题写 2 条，第一条写"没读到原文，下面只根据摘录" |

长度的起因：第一版没限字数，一条要点写到 400 多字，10 条 4000 多字，扫不过来。日报要的是"看完要点就能决定点不点开"，不是替他读完。

格式：

```json
{
  "A": {"title_zh": "…", "intro": ["…", "…", "…"], "for_you": "…", "length": "…", "read": true},
  "B": {…}
}
```

## 写法

- 中文，大白话，短句。术语非用不可时，括号里用一句话解释
- 只写原文里有的。没读到的不要补，数字不要估
- 不写预测分、方向名这类内部的东西
- 原文是中文以外的语言时，关键的专有名词可以保留原文

## 怎么读

| 来源 | 用什么 |
|---|---|
| X 推文、串推 | `opencli twitter thread <链接> -f json` |
| X 长文 | `opencli twitter article <链接> -f json`，正文在 `content` |
| arXiv | WebFetch 打开 `https://arxiv.org/abs/编号`，要细节再读 HTML 版 `https://arxiv.org/html/编号` |
| 其他网页 | WebFetch；读不到再用 `opencli browser` |
| GitHub | WebFetch 读 README |

一条最多花 3 分钟，读不到就标 `read: false` 换下一条。不点赞、不关注、不登录、不填表。

## 隐私（原样照抄 AGENTS.md「其他约定 · 隐私」）

仓库是公开的，谁都能看到。不存密钥和个人隐私信息。查资料、调接口时，不把 Luke 的邮箱、姓名、账号等任何个人信息写进外部请求（请求头、User-Agent、mailto、URL 参数都不行）；接口要联系方式时用通用写法 `weird-knowledge-research-bot`，或换别的查法。派 subagent 时，把这一条原样写进它的任务说明。
