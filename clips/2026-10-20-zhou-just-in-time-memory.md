### 内容要点（模型概括，不是原文）

方法名叫 JitMem（Just-in-Time Memory，"现用现整理的记忆"）。下面的数字注明出自第几节或哪张表。

**要解决的问题**

agent 连续做很多任务时，会把做过的事存成"记忆"，下次拿来用。现在主流做法是**写入时整理**：一个任务做完，马上把过程提炼成反思、心得、工作流、skill 或推理策略，存起来，以后按相似度取出。作者认为这有两个根本代价（第 1 节）：

1. 丢信息太早，而且丢了就找不回：将来某个任务恰好需要的细节，可能在提炼时被删了
2. 一份固定的提炼要服务所有未来任务：同一段经历对不同任务有不同的用处（比如一次家务操作，对一个任务是"怎么加热或冷却东西"，对另一个任务是"怎么把东西放到位"），但提炼时还不知道将来是什么任务

另外，想用强化学习训练"写入时的整理员"很难：存什么好不好，要等很多个任务之后某次被取到才知道，奖励来得太晚（第 1、3 节）。

**核心想法**

把整理从"写入时"挪到"读取时"：记忆库只存**完整的原始轨迹**（任务描述加每一步的观察和动作），不做任何提炼；等新任务来了，先检索出几条相关的原始轨迹，再由一个"记忆整理员"（curator）同时看这几条轨迹和当前任务，现场写一份只针对这个任务的简短简报，塞进执行 agent 的上下文。简报用完就扔，不存（第 1、3 节，图 1）。

两个好处：同一条旧轨迹，对不同的新任务能整理出不同的简报；整理员的奖励就是这一次任务成没成，当场就有，训练变简单。作者把它类比为认知科学里"情景记忆是重建出来的，不是回放出来的，回忆受当前目标影响"（第 1 节，引 Schacter & Addis 2007）。

**主要方法**（第 3、4 节，附录 A）

| 项 | 设定 |
|---|---|
| 四个部件 | 记忆库（存原始轨迹）、检索器、整理员（唯一要训练的）、执行 agent（冻结不训练） |
| 每个任务四步 | 检索最相关的 k 条原始轨迹 → 整理员写针对本任务的简报 → 执行 agent 带着简报做任务 → 做完由执行 agent 自己当裁判判断成没成，判成功的才存进记忆库 |
| 检索 | BM25（经典关键词检索），只比任务描述，不看轨迹内容；k=3（附录 A） |
| 整理员 | 从 Qwen3-8B（关闭思考模式）出发，用 GRPO（一种强化学习方法）训练 100 步；奖励只有"任务成没成"，没有额外的内容质量打分，不需要把相关任务分组 |
| 训练用的记忆库 | 先用不带整理员的执行 agent 把训练集跑一遍，按真实答案只留成功的轨迹，训练中固定不变 |
| 测试时的记忆库 | 从空开始，边做边长；10 个任务一批（τ²-bench 5 个一批），一批共享同一个记忆库状态 |
| 三个基准 | ALFWorld（文字版家务操作，140 道测试题）、WebShop（网上购物，500 道）、τ²-bench（客服对话加调工具，航空、零售、电信三个领域） |
| 三个执行 agent | Qwen3-8B、Gemini-2.5-Pro、GPT-5.4 |
| 对照组 | 不带记忆；ReasoningBank（提炼推理策略）；MemP（多粒度记忆条目）；SkillOS（用强化学习训练的 skill 整理员，最接近的前作）。都是写入时整理 |
| 算力 | 一台 8 张 H200 的服务器；训练一次 ALFWorld 约 21 小时，WebShop 约 27 小时（附录 A） |

**需要说清楚的边界**

- 作者自己承认：检索器是简单的 BM25，记忆库变大变杂后可能成为瓶颈（第 5 节）
- 作者自己承认：每个任务多一次模型调用（整理员）（第 5 节）
- 作者自己承认：简报的格式是人按每个基准手工设计的（第 5 节）
- 作者自己承认：τ²-bench 没有标准训练集，所以这个基准上只比了不训练的版本（第 4.1 节）
- "+3.9"那一项用的是**没训练**的 GPT-5.4 整理员，不是训练出来的 Qwen3-8B 整理员；"+16.2 / +16.3"是在最弱的执行 agent（Qwen3-8B）上，换成 Gemini、GPT-5.4 后提升是 6.0～10.9 点（表 1、表 2）
- 表 4 只数了执行 agent 这一侧的 token，整理员自己读 3 条原始轨迹、写简报的那次调用没算进去（整理员的输入上限设到 32768 token，附录 A 表 7）。"省 token"说的是执行 agent 的上下文更干净，不等于整套流程更省钱
- 写入时并不是什么都不做：只有执行 agent 自己判断"成功了"的轨迹才存进去，这本身是一道写入时的筛选，而且消融显示它有用（第 3 节、第 4.2 节）。所以准确说法是"写入时只筛不提炼，提炼留到读取时"
- "不训练也有竞争力"不是处处成立：Qwen3-8B 执行 WebShop 时，没训练的 JitMem-base（得分 32.5、成功率 11.7）低于 SkillOS-base（38.6、13.6），得分甚至略低于不带记忆的 33.3（表 1）
- 表 1 里 Qwen3-8B 和 Gemini 两组的"不带记忆"数字，和表 6 里 SkillOS 论文报告的数字一字不差；作者自己复现的更低（如 Qwen3-8B 做 ALFWorld 复现为 34.5 或 42.1，报告为 47.9）。正文没写清表 1 的基线是自己跑的还是沿用前作的数字（待确认）。作者为了让 Qwen3-8B 做 WebShop 的基线接近前作，在执行 agent 的提示词里加了一段搜索指导，并说调到了不高于报告值（附录 A、表 6）
- 结果是 3 次（τ²-bench 4 次）不同任务顺序的均值和标准差；不少差距在一个标准差附近，比如 Gemini 做 ALFWorld 时 JitMem-gemini 81.9±2.7 vs SkillOS-gemini 79.3±2.6（表 1）
- 三个基准都是模拟环境（文字家务、模拟网店、模拟客服），任务类型重复度高，同类旧轨迹容易检索到；在任务更杂、更长期的真实场景里效果如何，论文没有测
- 读取时整理不是这篇独有的：作者自己点名同期工作 MemHarness（Wu 等，2026a，副标题就是"记忆是重建的，不是回放的"）也在读取时整理；区别是 MemHarness 让同一个模型既整理又执行，而 JitMem 把整理员和执行 agent 分开，所以能换执行 agent（第 2 节）
- 和认知科学"重建式记忆"只是作者说的类比（parallels），论文没有做认知科学方面的论证

## 溯源

- 核心主张：agent 的跨任务记忆不要在任务做完时就提炼成心得或 skill，而应先存完整的原始轨迹，等新任务来了、知道要解决什么时，再针对这个任务现场整理成一份简报；这样不会过早丢掉细节，同一段经历能为不同任务整理出不同内容，整理员也能直接按这一次成没成来训练。
- 源知识：
  - [建构性记忆的认知神经科学：回忆过去与想象未来](../roots/schacter-2007-constructive-memory.md) · 关系：相近 · 强弱：强。作者第 1 节明说这一设计对应认知科学的观点：情景记忆是按当前目标和线索重建出来的，不是回放出来的，并引 Schacter 与 Addis 2007；只是类比，论文没做认知科学论证。
  - [ExpeL：大模型智能体是经验学习者](../roots/zhao-2023-expel.md) · 关系：挑战 · 强弱：强。经典做法（Reflexion、ExpeL、ReasoningBank 等）是任务做完就把轨迹提炼成心得或技能再存；JitMem 点名这类“写入时整理”会不可逆地丢信息、只能给出与问题无关的固定摘要，主张写入时只存原始轨迹、读取时再整理，并在三个基准上胜过同类方法。
  - [案例推理（基于案例的推理）](../roots/case-based-reasoning.md) · 关系：相近 · 强弱：弱（模型复核通过）。存原始案例、按新问题检索相似案例、现场改造再用、成功的才保留，和案例推理的“检索、复用、修正、保留”四步几乎同构；论文没引案例推理，是模型推断。
  - [惰性学习（对照：积极学习）](../roots/lazy-learning.md) · 关系：相近 · 强弱：弱（模型复核通过）。机器学习里“等查询来了再泛化”（惰性学习）对“事先泛化”（积极学习）的老区分，正对应 JitMem 的“读取时整理”对“写入时整理”；论文没用这个词，是模型推断。
  - [迈向人工智能的步骤（提出信用分配问题）](../roots/minsky-1961-steps-toward-ai.md) · 关系：直接源自 · 强弱：强。论文摘要和第 1、3 节直接用“信用分配问题”说明写入时整理难训练（存得好不好要很多任务后才知道），读取时整理把信用分配压成同一步、奖励立刻可得。
  - [信息处理不等式](../roots/data-processing-inequality.md) · 关系：相近 · 强弱：弱（模型复核通过）。写入时提炼是对原始轨迹的后处理，按信息处理不等式只会丢信息、不会增加，这正是论文说的“不可逆地丢信息”的信息论底层；论文没引它，是模型推断。
- 本质：这条新知识本质上是“重建式记忆”和“惰性学习”（把加工推迟到知道用途的那一刻）在 agent 跨任务记忆上的应用。
