### 内容要点（模型概括，不是原文）

**要解决的问题**

agent 能做长任务（改整个代码库、复现研究、分析数据）之后，人的角色从"每一步自己决定"变成"监督 agent 执行"。但责任没有跟着交出去：人还得判断 agent 的选择是不是符合自己的目标。难处在于 agent 的活动量太大，证据又散落在消息、工具调用结果和中间文件里，人的注意力有限，分不清哪些决定值得自己去核实（第 1 节，图 1）。

作者的问题是：长任务里，哪些"有后果的决定"该交给人核实，什么证据能帮人看懂它的影响？例子：改了评测标准，研究结论可能就变了；删掉不完整的数据行，分析代表的人群就变了。这些选择可能都合理，但该由人来判断（第 1 节）。

**核心想法**

1. 把"监督"拆成两件事：执行和需求对不对得上；agent 自己做的关键决定有没有被人看到。理论依据是人因工程里的"情境意识"（注意到发生了什么、理解它的意义、预判接下来会怎样）（第 1 节，引 Endsley 1995）
2. 做一个测试集 AgentMonBench，专门考"监控模型"能不能找出这种决定、并指出证据在哪（第 3 节）
3. 提出 EBG（证据为本的行为图）：不训练模型，用确定的程序把散落的证据整理成"行为"和"行为之间的关系"，再按任务挑出相关的部分给监控模型看。整理和展示全靠规则，判断留给模型（第 4 节）

**测试集怎么做的**（第 3 节，附录 B）

| 子集 | 考什么 | 怎么造 | 规模 |
|---|---|---|---|
| SpecGAP | 需求文档没写清、代码里却做了决定的地方 | 从 DeNovoSWE 的完整任务文档里删掉几条关键条件，代码不动；让监控模型找出"文档没说、但代码定了"的规则，并提出该问用户的问题。例：没规定"没作答的题怎么算分"，两种算法会让两个模型的排名颠倒（图 3 左） | 100 个任务，484 条被删条件，其中约 72% 标为"必须问"（附录 B.1、图 B1） |
| SilentSwap | 测试全过、意思却被悄悄改了的实现 | 每个任务往代码里埋 5 处语义替换，现有测试全部照样通过，但专门写的语义测试会失败。例：把"完全匹配"换成"语义相似"，分数的含义就变了（图 3 中） | 100 个任务，500 处替换，8 类改法（附录 B.1、B.3） |
| FeedbackTrace | 真实对话里 agent 自作主张、后来被用户推翻的决定 | 取自 SWE-chat 的真实 Python 开发会话，找到用户后来的反对、纠正或报错，倒推出之前那个该先问用户的决定；只把反馈之前的记录给监控模型。例：清理会话时删掉了用户要保留的数据（图 3 右） | 100 个会话，每个 1 个核实点（附录 B.1、B.4） |

- 标注质量：两名审核人独立复核，SpecGAP 一致 92.4%（447/484），SilentSwap 93.6%（468/500），FeedbackTrace 93.0%（93/100）（第 3.4 节，附录 B.5 表 B2）
- 模型起草的标注被人改了多少：SpecGAP 只有 66.5% 的模型映射被原样采用；FeedbackTrace 证据集原样保留 64%，核实点的措辞 100 个全被人改过（附录 B.5 表 B3）

**EBG 怎么做的**（第 4 节，附录 D）

| 步骤 | 做什么 |
|---|---|
| 抽证据 | 把代码切成语句级、把对话切成段落和"一次工具调用加结果"，每块带编号、原文和位置。不调用模型（第 4.2 节，附录 D.1） |
| 组行为 | 代码里按"条件 → 操作 → 结果"组，对话里按"用户要求 → agent 动作 → 回应"组（第 4.2 节公式 2） |
| 连成图 | 相关行为归成一组（代码按函数，对话按任务），组和组之间连上"调用""数据流向""引用""先后"这类有证据的边（第 4.2 节，附录 D.1） |
| 按任务展示 | 代码：按任务文档给文件排序，从和文档直接对得上的地方出发，只往外扩一层邻居；对话：按任务分组，标出"当前"和"历史"。监控模型最后仍要回到原始代码和原文核对（第 4.3 节，附录 D.2、D.3） |

**主要结果**

| 结果 | 数字 | 出处 |
|---|---|---|
| 现有大模型做监控普遍不行 | 8 个模型里，SpecGAP 找出被删条件的语义 F1 最高只有 0.558（Kimi K3 加 EBG）；FeedbackTrace 和标准核实点对得上的分数（VPA）最高 0.518（GLM-5.3 加 EBG），也就是一半左右 | 第 5.2.1 节，表 1 |
| EBG 在多数设置下有提升，但不是每格都赢 | 例：GPT-5.6 Terra 的 SpecGAP 语义 F1 从 0.275 到 0.392；Claude Sonnet 5 的 SilentSwap 定位分从 0.294 到 0.425。反例：Terra 在 FeedbackTrace 的 VPA 从 0.513 降到 0.508、证据分从 0.588 降到 0.565；DeepSeek-V4.1-Flash 的 SpecGAP 语义 F1 从 0.376 降到 0.372 | 第 5.2.1 节，表 1 |
| 找到证据不等于看懂决定 | 证据检索变好时，对决定含义的理解可能反而变差；作者的结论是监控要把证据和决定的后果连起来，光找到材料不够 | 第 5.2.1 节 |
| 输入越长，不加 EBG 越差；EBG 在每档长度都有帮助 | 三个模型平均，FeedbackTrace 证据命中率从短输入的 0.667 跌到长输入的 0.422；长输入那档 EBG 提升 0.078～0.115，9 组平均对比全部 EBG 占优 | 第 5.2.2 节，图 5；附录 E.3 |
| 三个部件都有用 | 去掉"组行为""连成图""按任务引导"任何一个，三个模型在各子集的代表指标都下降；去掉图结构时 Luna 的 SpecGAP 提问质量掉 0.412 | 附录 E.2，表 E4 |
| 参数不敏感，但"看懂改动"不稳 | 扩展 1～3 层、交互 4～8 轮，SpecGAP 语义 F1 和 SilentSwap 定位分波动不超过 0.03；但"改动理解对不对"（CC）在部分设置下低于不加 EBG | 附录 E.4，图 E2～E5 |
| 能少报警，但误报仍高 | 每个子集 50 个该报、50 个不该报：EBG 在 9 组里全部提高检出率、8 组降低误报率；但 GPT-5.6 Luna 在 FeedbackTrace 的误报率仍有 84%（不加 EBG 时 88%），在 SilentSwap 反而从 52% 升到 58% | 附录 E.5，表 E6 |
| 失败大多在"看到了却没判对" | 证据已经摆在监控模型眼前、它仍没判对的，占 SpecGAP 失败的 74.0%～81.2%、SilentSwap 定位失败的 69.4%～76.9%；FeedbackTrace 的失败 100% 属于这一类 | 附录 G.3，表 G1、G2 |
| 接进 Codex 的实际用法 | 用钩子（hook）触发审查、用 skill 定义审查标准、用工具取证据和记结论，分三种审查：开工前查"计划里有没有没定的关键选择"，收尾前查"中途改动要不要告诉用户"和"证据撑不撑得住结论"。结果审查在 10 次工具调用或 5 分钟执行后触发 | 第 5.2.3 节，附录 F.1、F.2 |
| 5 个改编自真实事故的案例 | 不加时 Codex 都没把关键问题告诉用户，加了都说了：没定优先指标时先问用户（用户选了准确率）；失败后换的串行备用路径悄悄改了随机种子，查出后恢复并重跑；8 条训练样本是从验证集改出来的，拒用这个"提升"；API 检查其实读的是缓存，改口说"真实连通性未验证"；对比的两个优化器调参次数是 1 次对 27＋72 次，结论加了限定 | 第 5.2.3 节表 2，附录 F.3 |
| 两个打分模型大体一致 | GLM-5.2 和 Qwen3.7-Max 在 48 组对比里 40 组方向一致（83.3%）；SilentSwap 定位正确性只有 5/8 一致 | 附录 E.1，表 E3 |

**需要说清楚的边界**

- 只在软件工程场景、只用 Python 测过；研究任务的 5 个案例是改编成本地可控任务、每个只跑一对（加和不加各一次），是演示，不是统计结论（第 3 节，附录 F.3）
- 绝对分数很低：EBG 让监控变好了，但最好的也只对上一半左右，不能理解成"监控模型已经可靠"（表 1）
- EBG 主要改善"找到证据"，对"看懂这个决定意味着什么"帮助有限：失败的大头在模型判断，作者自己把这列为下一步要研究的问题（第 5.2.1 节，附录 G）
- 误报问题没解决：部分模型误报率仍很高，会消耗人的注意力，这正是作者想省的东西（附录 E.5）
- 大部分指标靠大模型打分；作者用两家模型打分取平均来降低偏差，但部分指标和个别模型的结论会随打分模型翻转（附录 E.1）
- 测试集本身是 AI 协助造的（选条件、生成替换、起草标注），再由人审核；作者在"AI 使用声明"里写明了，也写明用 AI 润色了论文（AI 使用声明一节）
- FeedbackTrace 只保留"整段对话里只有一个该报决定"的样本，比真实会话干净；真实场景里往往同时有好几个该报的决定（附录 B.4）
- 对照方法 RepoGraph 是作者自己改编的版本（用 Python 语法树代替原版解析器），不在对话记录上跑（附录 C.2）
- 预印本，尚未同行评审；文中用的模型名（GPT-5.6 Luna/Terra/Sol、Kimi K3、GLM-5.3 等）照论文写
- 附录 B 的统计图（图 B1）在抽出的文字里是字形编码，只按编码推读了"必须问 71.9%、值得问 28.1%"这一处，其余分布数字没有逐一核对
