### 内容要点（模型概括，不是原文）

**要解决的问题**

agent 的外壳（Claude Code、Codex 这类跑 agent 的程序）每一步都调一次大模型，长任务又慢又贵；作者引用的数字是，给一个公开排行榜评测 agent 花了约 4 万美元（第 1 节）。但每一步的调用，多数最后落在一道选择题上：下一步调哪个工具、参数填哪个值、要不要停、要不要反思。JEV 这类"决策模型"只打选项的概率、不生成文字，一次调用约是大模型的 28% 时间、2.6% 价钱（第 1 节）。问题是：决策模型都是在固定的题目上做出来、考出来的，放进一个真在跑的 agent 里会怎样，没人测过；在 agent 里，一步选错会影响后面每一步，而且 agent 会走到"自己犯错之后"的状态，固定题库里几乎没有这种状态（第 1 节）。

**核心想法**

作者的假设是：决策模型要在 agent 里面考、只在有把握时用、用 agent 自己走到的状态来训，才帮得上忙（第 1 节）。对应做了三样东西：

1. **AgentDecisionBench**：分三级考决策模型。L1 单独的选择题；L2 在录下来的 agent 运行记录里每一步答题、只打分不执行；L3 真接管一个在跑的 agent，选错了后果会传下去（第 3 节）
2. **JevAgentHarness**：把外壳里每一类例行选择包成一道带类型的选择题交给决策模型，只有把握超过门槛才采用，否则照旧让大模型定（第 4 节）
3. **AgentDecision-4B**：一个开源 4B 模型，用 agent 实际走到的状态（含犯错后的状态）训练，以 JEV 的答案当标签（第 5 节）

**交出去值不值：一条门槛公式**（第 2.1 节，附录 A 命题 1）

决策模型的把握 c 如果等于它答对的概率，那么交给它划算的条件是 c ≥ 大模型在这类选择上的正确率 − 省下的调用费 ÷ 选错一次的代价。也就是说，决策模型可以比大模型稍微差一点，只要省下的钱够抵多出来的风险。实际做法：先在单独的 150 个任务上让决策模型"影子模式"陪跑（只答不执行），从记录里估出大模型正确率、调用费、选错一次让成功率掉多少，再按每个置信区间实际的正确率找门槛（第 2.1 节）。用 JEV 配 Gemini 3.5 Flash 时，拟合出来工具选择的门槛是 1.00、参数是 0.99，就是只采用几乎确定的答案（第 2.1 节）。

**五种交法**（第 2 节，图 3）

| 方式 | 意思 |
|---|---|
| REPLACE | 决策模型直接定，不问大模型 |
| CASCADE | 决策模型有把握就定，没把握交大模型（文中主力） |
| ASSIST | 决策模型先缩小候选，大模型从里面挑 |
| GUARD | 大模型提方案，决策模型批准或打回 |
| TRIGGER | 决策模型决定要不要跑某个可选步骤（如反思） |

8 个决策点（工具、参数、动作、写记忆、读记忆、反思、停止、换便宜模型）× 5 种方式，40 种组合都实现了（附录 A）。

**实验设计**（第 6 节，附录 E）

先预注册模型、任务和检验方法。第一阶段每种交法单独测，"不劣于"只用大模型（成功率掉不到 3 个点，τ²-bench 上 5 个点）且更便宜的才留下，11 个检验用 Holm 法校正；第二阶段在 500 个新任务上把留下的交法组合起来测，第二阶段的方案在看第一阶段结果之前就登记好。测试环境主要是作者自建的 DecisionGym（模拟网店客服台，69 个工具选项里一半是近似重复的干扰工具，每一步都知道哪些下一步算对），加上 τ²-bench、ALFWorld、SWE-bench Verified、Terminal-Bench（第 3 节）。

**主要结果**

| 结果 | 数字 | 出处 |
|---|---|---|
| 单题分数排不准 | 单题工具选择最准的 StartLux-9B（92.2%）接管 agent 只完成 69.5% 的任务；AgentDecision-4B 单题 89.3%，任务完成 91.5%；JEV 82.0%。单题、逐步、整任务三级的分差分别是 5.1、19.7、57.5 个点 | 第 7.1 节，图 4 |
| 逐步准确率排得较准 | 逐步准确率和任务完成率的排名相关 0.84；差距出在"该先问客户"的状态：AgentDecision-4B 答对 67.4%，JEV 58.3% | 第 7.1 节 |
| 不设门槛就掉分 | 工具选择全交给 JEV，成功率掉 19.0 个点；JEV 给大模型缩成 3 个候选，掉 7.8 个点、省 53.7%；固定门槛 0.5 掉 21.5 个点 | 第 7.2 节，表 2 |
| 设了门槛不掉分 | 配 Flash 时 JEV 做了 27.2% 的工具选择和 20.8% 的参数选择，省 14.2%，500 个任务结果一个没变；配更弱的 Flash-Lite 时门槛把工具选择全留给大模型，什么也没省 | 第 7.2 节 |
| 只省不了钱的方式 | 停止前加 GUARD 成功率不变但贵 6.2%；让 JEV 决定 Flash-Lite 的步骤要不要升到 Flash，贵 36.2% 且成功率没明显提高 | 第 7.2 节 |
| 换了环境不一定成立 | 在 τ²-bench 上重新拟合后，最省的那个交法掉 8.1 个点，没能证明能迁移 | 第 7.2 节 |
| 用训出来的 4B | DecisionGym 上便宜 86.3%、快 2.5 倍，成功率掉不到 3 个点；500 个新任务里它做了 99.9% 的工具选择、75.0% 的参数选择，每个任务省 4.5 次大模型调用；每次答题中位 31 毫秒，Flash 一次 809 毫秒 | 第 7.3 节 |
| ALFWorld 上专门训的 4B | 便宜 89.0%、快约一倍，成功率 90.7%→95.0% | 第 7.3 节，表 1 |
| 编程 agent 收益小 | 让 JEV 决定每一步交给强模型还是快模型，省 7.0%～10.5%，成功率依外壳而定（mini-SWE-agent 用 DeepSeek-V4 掉 1.0 个点，SWE-agent 掉 6.0 个点，pi 在 Terminal-Bench 2.0 上升 7.9 个点） | 第 7.3 节，表 1，附录 C.2、C.3 |
| 训练主要靠监督微调 | 在 agent 自己的状态上做监督微调，换了工具名和说法的任务上逐步准确率 52.9%→98.4%，任务完成 13.5%→96.0%；只花 2.2 GPU 小时；再加强化学习（GRPO）多花 4.5 GPU 小时和 26.53 美元，没测出提升；不做监督微调直接强化学习，没有任何提升 | 第 7.4 节，表 3，附录 D.3、D.4 |
| 加公开数据有代价 | 再加公开的工具调用数据，单题准确率 78.8%→85.1%，但换了说法的任务完成率 96.0%→91.5% | 第 7.4 节 |
| 训练成本回本 | 训练加校准 AgentDecision-4B 共 192.93 美元，按第二阶段省下的钱，跑 5,759 个任务回本；整个研究的 API 花费 2,383.27 美元 | 附录 F |
| 投票替代不了训练 | 现成决策模型多数投票、几个一致才交出去，都比不上训过的 4B；现成模型在"该先问"的状态上犯的错是同一批 | 附录 G.8，表 35 |

**会在哪儿失败**（第 7.5 节，附录 G.7、G.9，附录 I）

- 在不可撤销的一步上有把握地选错，任务就完了。JEV 失败的 34 个任务，全部始于一次不可撤销的错误工具选择，通常是该问客户的时候直接取消了订单
- 遇到没见过的规则会翻车：训练时没见过"按客户等级决定取消还是发货"的 4B，在 10 个客户的难题上几乎包揽这类选择却只对 81.6%，agent 只完成 3.0%（只用大模型 88.0%）；重新拟合门槛后 JEV 恢复，用这条规则再训一轮，4B 的准确率 76.5%→95.3%
- 换了工具名和题型后，两个 4B 模型照样很有把握、继续接管大部分选择，成功率掉 6～7.5 个点，门槛没能自动把选择交还给大模型
- 还会调用大模型的方式（如 GUARD）省不了多少

**需要说清楚的边界**

- 任务和提示词全是英文，大部分实验用 Gemini 当 agent 模型；换语言、换模型，值得交出去的选择可能不同（局限一节）
- 主要检验是"不劣于"检验，只能说明成功率掉得少于设定的幅度（3 个点），不等于"一样好"（局限一节）
- 门槛和训出来的模型都贴着某个 agent 自己的运行记录；换 agent、换工具、换任务类型都要重新拟合，要最好效果还得重新训（局限一节）
- 编程 agent 的动作是自由文本，决策模型只能决定"这一步交给哪个大模型写"，所以省得少；"只读文件的步骤交给快模型"没能稳定省钱，因为 JEV 分不清哪些步骤只读（局限一节，附录 C.3）
- DecisionGym 是作者自建、由少数模板生成的；附录承认按模板查表就能答对大部分共同状态，训过的模型的领先多半反映了生成器的套路，真正拉开差距的是训练里没见过的状态（附录 D.10，表 22）
- 表 1、图 4 和换说法的任务都是第一阶段之后补做的实验，不在预注册的检验里，只算描述性结果（第 7 节，附录 E）；作者还披露了一次轻微的"偷看"，严格看第二阶段关于 4B 的两项检验应算探索性（附录 D.10）
- 没和 RouteLLM 这类学出来的路由器在同一批任务上比（局限一节）
- 只测了正常输入，没测对抗性输入和策略注入；决策模型当 GUARD 时，在 Flash-Lite 上放过了 40.7% 的错误收尾，所以作者说它不能当不可撤销动作的唯一关卡，适配层失败时会跳过、也不能当安全边界（伦理一节）
