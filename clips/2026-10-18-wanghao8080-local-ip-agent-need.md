## 原文

刚刚了解到一个真实的 AI Agent 需求，是一位做同城 IP 的同学提出来的。服务客户前，他都要根据客户的行业，找对标账户，做各种文案、选题与用户分析，他们是个小团队，同时接到 5、6 客户就忙不过来了。搞些 Agent + SaaS 解决这个问题，定价 ￥399 /月，做到 500 用户，一年￥2,000,000利润。

## 溯源

- 核心主张：小型内容服务团队的产能卡在服务前的人工调研和内容准备上（找对标、写文案、定选题、做用户分析），把这些活交给 agent 做成按月订阅的工具，就是一门可卖给同类团队的生意。
- 源知识：
  - [待完成的任务](../roots/jobs-to-be-done.md) · 关系：相近 · 强弱：弱（待 Luke 确认）。需求直接来自一线从业者要完成的具体任务（每接一个客户都要做的调研和文案），而不是先想功能再找用户。
  - [约束理论](../roots/theory-of-constraints.md) · 关系：相近 · 强弱：弱（待 Luke 确认）。“同时接到 5、6 个客户就忙不过来”说明整条服务链被人工调研这一环卡住，产品要解的正是这个瓶颈。
  - [服务即软件（卖工作而不是卖软件）](../roots/service-as-software.md) · 关系：相近 · 强弱：弱（待 Luke 确认）。让 agent 直接承担原本由人做的服务性工作（对标分析、选题、文案），和“服务即软件”的思路一致；作者没有引用。
- 本质：这条新知识本质上是“找到瓶颈任务、让 agent 替人干活”（约束理论 + 服务即软件）在小型同城 IP 内容服务团队上的应用。
