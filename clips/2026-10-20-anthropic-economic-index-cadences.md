### 内容要点（模型概括，不是原文）

网页、PDF 正文、附录的文字部分都读完了。图和表大多是图片，读不出里面的具体数值，下面只用正文文字里写明的数字。

**要解决的问题**

一年前大家用 Claude 主要是聊天；现在 Claude Code 和 Cowork 里多是长时间跑的 agent 任务，光看聊天记录已经看不清 AI 在经济里做了什么。这一期改了数据管道：改成每小时抽样（以前每期只抽一周）、新加一个分类器给每段对话标"产出物"（artifact）、按月公开更细的数据，并第一次把一份问卷和真实使用数据连起来看（引言）。

**核心想法**

三章三个视角：用法跟着现实生活的节奏起伏（第 1 章）；看每段对话最后交出了什么东西，以及这东西花了多少算力、AI 自己拿了多少主意（第 2 章）；问用户本人怎么看 AI 对自己工作的影响，再和他们的使用方式对照（第 3 章）。

**主要方法**

| 做法 | 说明 |
|---|---|
| 隐私保护的分类 | 对话只由另一个 Claude 实例读和分类，样本太少的格子删掉（第 1 章脚注 1） |
| 产出物分类 | 30 多个类别，每段对话只标最主要的一个（第 2 章，附录第 2 章有完整提示词） |
| 任务映射 | 把对话映射到美国 O*NET 职业任务（换成 30.2 版，先选"详细工作活动"再选任务），再用美国劳工统计局 BLS OEWS 2025 年 5 月的工资数据算职业工资（附录第 1 章，第 2 章脚注 1） |
| 自主程度 | 1～5 分，从"没有"到"极高"，看 AI 自己做了多少决定（第 2 章） |
| 问卷联动 | 2026 年 4 月上线的 Economic Index Survey；用隐私保护方法和 5 月中到 6 月初的使用数据相连，每人最多抽 20 个会话，少于 5 个会话的剔除，最后约 9,700 人（第 3 章） |
| 协作方式 | 指令式、反馈循环、任务迭代、学习、校验五种；前两种算"自动化"（第 3 章脚注 8） |

| 自报收益 | 速度、范围、质量变好：86%、82%、69%；省下外包费用 27%；学得更多 68%；技能更值钱 57% | 第 3 章 · 工作 |
| 放手和学习 | 认为技能更值钱的比例随自动化占比上升；"学得更多"的比例基本持平 | 第 3 章 · 工作 |
| 男女差异 | 控制职业后，女性的 Claude Code 会话占比低 0.24 个标准差（6.3 个百分点），自动化占比低 0.33 个标准差（7.3 个百分点），在聊天里花的时间更多 | 第 3 章 · 性别 |

**需要说清楚的边界**

- 这是厂商调查：Anthropic 卖的就是 Claude，数据全部来自 Claude 用户，分类也由 Claude 来做
- 作者自己承认：问卷不代表一般人群，受访者偏技术和管理岗，剔除了不常用的人（第 3 章）
- 作者自己承认："越放手越乐观"可能是选择效应，最热衷 AI 的人本来就更愿意放手；控制了用户注册时长后结果变化不大，但不能完全排除（第 3 章）
- 作者自己承认："放手的人学得一样多"是自评，技能照样可能退化，数据排除不了（第 3 章）
- 作者自己承认：token 和工资的关系噪声大、有明显例外（药剂师、医生类职业）；token 数没按模型调整（第 2 章，脚注 3）
- "38% 把丢工作的预期归因于 AI"是上限，因为这一问把职责变化和丢工作放在一起问（脚注 11）
- 问卷是分档作答，图 3.3 的斜率会偏向 0，作者只做定性比较（脚注 4）
- "价值"是用对话映射到的职业工资估出来的，不是这段产出的真实价值；"更像增强劳动而不是替代劳动"是作者的解读，原文用的是"看起来"
- 网页和 PDF 有一处不一致：问睡眠建议的高峰，网页第 1 章写凌晨 5 点左右，PDF 第 1 章写凌晨 3 点左右（两个版本的引言都写 5 点）
- 容易误传成"AI 让人更乐观"或"Claude Code 让 AI 更聪明"：前者只是相关，后者作者说的是"用的产品比底层模型更要紧"，而且自主程度是分类器打的分
