## 原文

微软搞的一个去中心化多AI框架：Agensh，去掉“AI大管家”，让最多1024个Agent自协作，自己商量、分工、干活

结果是人越多越快，128个AI半小时就突破的进度，1个AI 两小时都达不到，有意思的是AI还自发长出了组织能力

随着AI数量增加，涌现出了类似人类社会的现象：
8个AI：先约定接口，然后各自独立开发

32个AI：出现多人评审，发现bug会撤回批准、要求返工

当128个AI：出现专业分工和标准化流程，还发明了一套整合协议（更新+测试+发哈希验证），后来被其他AI复用和修订

当1024个AI：出现专职的“整合者”角色，某个AI失败后会有专长者接手，组织不再依赖任何单一个体

现在的多AI系统一般是“一个老板带一群员工”，老板要负责派活、协调、汇总

Agensh的解法是，不要老板，每个AI都拿到同样的任务说明，然后循环做五件事：

1、看进展，项目做到哪了？别人发现了什么？
2、认领任务，并公开声明（撞车了就和对方私下协商）
3、动手干活，写代码、跑测试
4、自检结果，不达标就继续修
5、提交合并，提交Pull Request，把成果并入主干

配套的是三件套基础设施，很像GitHub工作流：共享工作区（Git管代码和合并冲突）、消息接口（频道公告+私聊，类似Slack）、共享上下文（记录事实、失败教训、任务认领的团队Wiki）

这对费时费力的长时工程倒是一种新解法。在把单个模型做大和让单个模型多想一会儿之间给出了第三条路，固定模型不变，增加Agent数量，让整体能力提升

## 溯源

- 核心主张：不设中心调度，让大量 agent 拿同一份任务说明，通过共享代码库、消息频道和团队 Wiki 自己认领、干活、自检、合并；规模越大进度越快，还会自发长出评审、专业分工、整合者这类组织结构，增加 agent 数量成了模型变大、多想一会儿之外的第三条提升路径。
- 源知识：
  - [痕迹协调（stigmergy，又译共识主动性）](../roots/stigmergy.md) · 关系：相近 · 强弱：弱（模型复核通过）。agent 不靠老板派活，而是读共享代码库和团队 Wiki 里别人留下的进展、教训、认领记录来决定下一步，正是“通过环境里的痕迹间接协调”；维基百科就把维基和开源项目当作人类社会里的例子。论文本身没用这个词。
  - [黑板系统](../roots/blackboard-system.md) · 关系：相近 · 强弱：弱（模型复核通过）。多个模块围绕一块公共区域读写、一步步把问题往前推，是 AI 里最早的去中心协作架构；Agensh 的共享工作区和共享上下文就是这种做法，论文没做这个对比。
  - [Anthropic 多智能体研究系统](../roots/anthropic-2025-multi-agent-research-system.md) · 关系：挑战 · 强弱：强。Agensh 论文（arXiv 2609.26781）明引 Anthropic 多智能体研究系统等“编排-工人”架构，认为它们受限于主 agent 的处理能力；推文说的“去掉 AI 大管家”就是冲着这种架构去的。
  - [分工](../roots/division-of-labour.md) · 关系：相近 · 强弱：弱（模型复核通过）。斯密说分工受市场规模限制；这里 agent 越多，越自发长出专职评审、整合者等分工，是同一规律在 agent 群体里的再现（推断）。
  - [布鲁克斯定律](../roots/brookss-law.md) · 关系：挑战 · 强弱：弱（模型复核通过）。布鲁克斯定律说加人会因沟通成本反而变慢；Agensh 报告人越多越快，靠共享 Wiki 和异步合并压低协调成本。但论文数字显示越往后每加一个 agent 的边际收益越小（五道最难题 1 到 128 个 agent 平均通过率 19.31% 到 28.78%，据论文摘要页，未逐字核对 PDF），并没有推翻沟通成本这一点。
- 本质：这条新知识本质上是“通过环境里的痕迹间接协调”（stigmergy）加上开源协作那套“认领—提交—评审—合并”流程，在大量编程 agent 协作上的应用；它挑战的是“必须有一个主 agent 派活”的编排-工人架构。
