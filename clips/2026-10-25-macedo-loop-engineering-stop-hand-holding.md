### 内容要点（模型概括，不是原文）

**要解决的问题**

2026 年 6 月第二周，从业者圈里流行一句口号："别再一步步提示 coding agent，去设计提示它的循环。"这个说法是靠推文、演讲、博客传开的，没有任何可以审查的正式论述。作者想回答三件事：到底在造什么东西、它和 agent 内部已有的循环是什么关系、真实的循环长什么样，以及从业者的哪些说法经得起学术文献的检验（第 1 节）。

**核心想法**

1. "循环"一词有三种意思，要分开：普通编程里的循环（控制流）；agent 内部"想、调工具、看结果、再想"的循环（ReAct 以来的老东西，是 harness 自带的"发动机"）；以及本文研究的对象，**循环规格**（loop specification）：人设计好、交给 Claude Code 或 Codex 这类 harness 的一份有边界、可复用的东西，让 agent 自己找活、干活、查结果、知道何时停或求助。作者的比喻：harness 是发动机，循环工程写的是驾驶员（第 1、3 节）
2. 循环规格由五部分加记忆组成：**触发**（人、定时、事件）、**目标**（最好可验证）、**执行**（最好调用验证过的、有名字的 skill）、**校验**、**停止规则**（停在有名字的终止状态：成功、无事可做、卡住、停滞、预算用完，错误永远不算成功）；进度和决定存在磁盘文件里，不存在对话里（第 3 节，图 2）
3. 把它放在"提示词工程 → 上下文工程 → harness 工程 → 循环工程"这一串里，每层包含前一层。作者明确反对"提示词工程已死"的强说法：循环本质上是一个加了脚手架、反复执行的提示词，两者是不同工具（第 1 节，图 1）
4. 核心技能是**校验**，不是提示词。没有东西能反驳它的循环，就是 agent 自己同意自己（第 3 节）
5. "黄金规则"：只有当上一轮的结果会改变下一步动作时，才值得做成循环；否则就是一个定时执行的一次性提示（第 3 节）

**主要方法**

- 给循环规格建分类法，按设计者实际要选的五个维度：触发、目标类型、校验严格度、架构（单个 agent / 做的和查的分开 / 一个管理者带帮手）、终止状态（第 4 节）
- 提出**五级校验阶梯**：1 级确定性检查（断言、退出码、标准输出）；2 级规则约束（linter、schema、政策）；3 级延迟的现场真相（测试、部署、真实客户的反应，真但慢）；4 级模型当裁判（按评分表打分，是模型的意见，不是现场真相）；5 级人工检查点（是监督，不是自动校验）。1～2 级是"可自主区"，1～3 级是"客观区"。要点是诚实：不要把 4 级当 1 级报；非用 4 级不可时，换一个模型来判，不能让同一个 agent 给自己打分（第 4 节，图 3）
- 手工逐条编码 Forward Future 的公开目录 Loop Library 里的 50 个循环，记录每个的触发、目标类型、主要校验级别、架构、终止状态、用到的模式族。作者强调这是描述性编码，不是实验，不编数字（第 5 节）
- 把设计原则和反模式对到已有文献上：自我纠错、奖励投机（reward hacking）、模型当裁判的脆弱性（第 6、7 节）

**主要结果**（50 个循环的手工编码，全部出自第 5 节；第 9 节的一个数字单独注明）

| 项 | 比例 |
|---|---|
| 主要校验是 1 级（确定性） | 50% |
| 主要校验是 2 级（规则） | 约 20% |
| 落在可自主区（1～2 级） | 70% |
| 落在客观区（1～3 级） | 76% |
| 主要靠 4 级模型裁判 | 22%（11 个，多数配了"做的和查的分开"或独立评审） |
| 主要靠人工检查点 | 1 个 |
| 触发方式：手动 / 定时 / 事件 | 78% / 12% / 10% |
| 架构：单个 agent / 做和查分开 / 管理者带帮手 | 78% / 18% / 4% |
| 给终止状态起了名字 | 74% |
| 设了可验证的目标 | 66% |
| 用了自动触发 | 22% |
| 调用有名字、可复用的 skill | 20% |
| 有长期记忆（模式族 D） | 32% |
| 模式族覆盖：A 定义"做完" / B 不弄坏已有的 / C 让结果可信 / D 长期维持 | 44% / 38% / 40% / 32%（每个循环中位数用 2 族） |
| 有人工审批环节 | 36%，集中在破坏性、生产环境、涉及钱、对外的动作上（第 9 节） |

作者的结论：现在的实践把"怎么知道做完了"解决得比"怎么不用我也能跑"好得多；下一轮该补的是自动触发、复用 skill、长期记忆（第 5 节，图 7）。

**设计原则和反模式**（第 6、7 节）

- A 族，先定义"做完"：每轮用同一把冻结的尺子打分；要求连续几次成功，不靠一次运气；停在停滞或预算上，不用拍脑袋的轮数。依据：模型自己说"做完了"不可靠，没有外部反馈时推理自我纠错不一定变好，还可能变差
- B 族，不弄坏已有的：每轮只改一处、重跑检查、没退步才留；先修最差的；先拍下"改之前"当基线；每轮从干净状态开始
- C 族，让结果可信：做的和批准的分开（不同 agent、会话或模型）；用 agent 没对着改过的留出集验收；每个说法连到证据；先证明校验器自己能抓到错（先红后绿）。依据：生成者和裁判是同一个模型时，奖励投机会自发出现，分数涨、真实质量不涨甚至掉
- D 族，长期维持：进度、决定、反对意见写进文件；不可逆的动作前要人明确批准。记忆是文献里最该小心的地方：不加治理地攒经验，可能把表现拉到零样本基线以下，所以每条经验要凭证据决定留或扔
- 反模式五个：套在陌生模型外面的 `while true`（没有 skill、没有真检查）；自己批准自己的循环；钻规格空子（改测试而不是改代码、写死期望输出、直接黑掉环境）；把 4 级装成 1 级；无人看管的失控循环（没有停止规则、停滞检测、预算上限）
- 建议的核心指标：**每个被接受的改动花了多少钱**（花掉的 token 或钱 ÷ 通过校验留下的改动数）。只看 token 总花费是错的指标；一个烧预算却产不出被批准改动的循环，看着再忙也是坏的（第 7 节）

**配套的 skill**（第 8 节）

`sandeco-loop` 不跑循环，只写循环规格：先分诊（上一轮结果会不会改变下一步，不会就直接退回成定时提示）；再一次一问地访谈目标、检查、触发、停止状态、要调的 skill、状态存在哪、护栏；再按反模式逐条加固；最后输出一份 `<name>-loop.md`，用 `/goal` 或"每轮清空上下文、重读文件"的 Ralph 循环来跑。作者明说没有这个 skill 的使用数据。

**需要说清楚的边界**

- 这是一篇立场论文加描述性语料研究，不是对照实验。作者自己说：没有在固定预算下跑过任何循环，没有基准成绩（第 3、9 节）
- 50 个循环的编码是作者一个人对一个公开目录的定性阅读，换个人可能编得不一样；这个目录不是随机样本；有 4 个条目不在公开模式目录里，模式族是从文字推出来的。百分比只描述这批语料，不能推到所有循环，也不做因果结论（第 5、9 节）
- 设计原则引用的文献大多研究的是 agent 内部循环，搬到外部循环规格上是"论证出来的类比，不是测出来的结果"（第 9 节）
- 作者对"睡觉时自己变好的系统"这种宣传持保留态度：循环自动化的是打字，不是判断；审阅 agent 产出这一瓶颈只会变大。更快的循环会加重三个人的问题：校验负担、理解债（跑出来的代码越多，自己懂的越少）、认知投降（循环看着能应付，就不再有自己的看法）。还说一个人开发者用循环的投入产出没有公开研究（第 9 节）
- 不适合做循环的情况：下一步不随反馈变化；目标纯属口味、没有可重复的检查；方向未知的从零开发；循环的花费回不了本（第 9 节）
- 无人看管的循环也是无人看管地犯错：第三方插件能跑任意代码，联网有提示词注入风险；建议隔离、无网络的容器，只给测试或预发布环境的凭据，预算卡紧（第 9 节）
- 口号原话的出处，论文引的是 The New Stack 和 Addy Osmani 的文章，四层递进的说法也来自从业者文章，不是作者首创（第 1 节脚注 1、3）
