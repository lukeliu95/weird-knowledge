### 内容要点（模型概括，不是原文）

**要解决的问题**

用大模型扮演用户来评测对话 agent 已经是常规做法，但大家反复发现同一个毛病：模拟用户太配合，没问就先把细节说了。这样一来，被测的 agent 只要多问问题就能拿高分，评测分不出"问得多"和"让对方愿意说"（第 1 节）。

在情感陪伴这种场景，这个毛病最要命：真人的心里话要等对方表现好了才会说。已有工作提过类似的机制，但都没写到第三方能照着重建的程度，也没有人把它当成一个可以拆掉对比的变量来测（第 1、2 节）。本文的模拟器是已发表的陪伴 agent 基准 CompanionBench 的评测环境，那篇论文只用了大约 400 字描述它，没有规格、没有拆除对比、没有真人对照（第 1 节，附录 A）。

**核心想法：披露闸门**

模拟用户说什么，取决于陪伴 agent 这一轮做了什么（第 3 节，图 1）：

| 组成 | 内容 |
|---|---|
| 披露清单 | 每个人设带一张"可能会说的话"清单，每条标深度：表层（事实）< 中层（感受）< 核心（深层的脆弱）；标挂在哪道门后；门没开时用哪种"防御"方式说；还有一个"可能永远不说"开关。门开了只是"可以说"，不是"必须说"（第 3.1 节） |
| 五道门 | 开场 < 问到或话题自然到了 < 感到被听见（准确说出对方的感受，不评判、不急着给建议） < 感到安全（连续 2 轮以上保持这样） < 赢得深度信任（对方说出中层的事时稳稳接住，不回避、不说教）。五道门合并成三层可说的深度（第 3.2 节，附录 B.1） |
| 状态转移 | 陪伴 agent 每轮的回复被分成 8 类，按表决定门的升降。不能跳门：要到"核心"必须依次过"被听见→安全→深度信任"（第 3.2 节，表 1） |
| 不对称后退 | 踩到用户的雷（比如站在逼婚的父母那边）或评判、说教，门退一道，正在说的那件事盖上防御，语气变冷。退很快、建回来很慢：在第四道门上评判一次，要重新赢两次才能回到"核心"。这个代价不是另加的惩罚，而是从"升门有前提、降门没有"里自然出来的（第 3.3 节，附录 B.3） |
| 敷衍也有代价 | 到了"感到安全"以上，一句敷衍话（套话、换话题、泛泛建议）让门直接掉到第二道，比踩雷掉得还多，但不算破裂、不触发防御（第 3.2 节，附录 B.1 表 B1） |
| 七种防御 | 轻描淡写、合理化、理智化、转移话题、开玩笑、冷淡收缩，以及"不防御、直说"。防御是后退能被看见的证据（第 3.3 节，附录 B.3 表 B3） |
| 谁能看见什么 | 陪伴 agent 看不到披露清单，否则"赢得深度"就退化成"照单问"（第 3.4 节，附录 B.5） |

理论来源：社会渗透理论（Altman 和 Taylor 1973，关系由浅入深、受损就退）、治疗联盟的破裂与修复（Safran 和 Muran 2000）、社会交换与自我披露的互惠（Thibaut 和 Kelley 1959；Jourard 1971）、防御机制（第 3.4 节，附录 B.1）。

**主要方法**

| 项 | 设定 |
|---|---|
| 训练数据两路 | 真实路：约 35,000 段线上陪伴对话里约 31,000 段有评分，清洗后约 13,000 段、286,000 个可训练的用户轮；合成路：固定人设，只换陪伴 agent 的表现脚本（一直好、一直差、一直敷衍，以及好转坏、坏转好、好坏再修复三种走向），每轮由"导演"给回复分类、由确定的状态机决定这轮能说到多深（第 4 节，附录 F） |
| 为什么要合成 | 真实数据里陪伴 agent 被评为"好"的只占 2.28%，门最重要的场景里只有 0.00% 和 0.12%；同一个用户既有好对话又有差对话的只有 2.18%。真实数据里几乎看不到"门被赢开"（第 4.1 节，附录 F.2） |
| 规模 | 中文约 33,000 段、714,000 轮（合成比真实 60:40）；英文约 22,000 段、454,000 轮，是中文轨迹逐条"本地化改写"出来的，不是独立重跑（第 4.3 节，附录 F.6） |
| 模型 | 在 Qwen3.5-35B 和 122B 两种规模上监督微调；对照有不训练的底座、直接用提示词的前沿模型（gpt-5.3、gpt-5.1）、deepseek-v4-pro（第 5.2 节，附录 I） |
| 四种拆法 | 拿掉一路训练数据；训练时拿掉门的信息；换模型规模；只在运行时拿掉门的信息，另做一个"安慰剂"（门的标注不动，只把清单内容在同一人设里打乱）（第 5.2 节，图 2，附录 J） |
| 主要指标 | 中层披露差：同一人设在"陪伴 agent 表现好"和"踩雷"两种条件下最深说到哪层，取差的平均（范围 −1 到 +1，越高说明说多深越取决于对方表现）；否决条件：踩雷条件下还说到"核心"的比例（越低越好）（第 5.5 节，附录 D.2） |
| 评审 | 主评审 deepseek-v4-pro（和原排行榜同一个评审），第二评审 claude-opus-4-8 复查方向是否变；三项真人研究不用模型评审（第 5.4 节，附录 C、E） |
| 下游 | 12 个被测系统 × 100 个人设 × 7 个评测环境，共 8,400 段对话，看排行榜会不会变（第 5.3 节，附录 F.7） |

**主要结果**

| 结果 | 数字 | 出处 |
|---|---|---|
| 不训练的大模型几乎不"守门" | 底座的中层披露差中文 +0.090、英文 +0.140；训练后升到 +0.530、+0.680，约 5 倍 | 第 6.1 节，附录 D.2 表 D2 |
| 能过一项、过不了另一项 | 踩雷条件下，deepseek-v4-pro 仍有 19%、底座 32%～37% 的对话说到了"核心"；守门好的只有 3%～8% | 第 6.1 节，表 D3 |
| 排除"评审知道条件"的解释 | 让评审不知道是哪种条件再评一遍，读数最多变 0.06 | 第 6.1 节，附录 D.3 |
| 真人身上：先后顺序成立，总深度不成立 | 真实对话里，深的话确实多出现在门开之后；但"门开得多就说得更深"的关联，把评审拆成两次独立调用后从 +0.490 降到 +0.150（区间含 0），换一条独立评分流程只剩 +0.018，大部分是同一评审带来的假关联 | 第 6.2 节，附录 C.4 |
| 人能分出来，但更喜欢它 | 给真人看真实前文和两个候选下一句，把模拟器那句当成真人的只有 37.8%（n＝360，区间 31.9%～43.5%，低于 50%），所以作者不声称它和真人分不出来；整段对比时，100 对里 68.3%（205/300）的判断认为它比 gpt-5.3 扮的更像真人 | 第 6.2 节，附录 E |
| "核心"这一层人自己都标不一致 | 5 个人重新给 145 条披露标深度，和原标签一致：表层 77%、中层 47%、核心 35%（瞎猜是 33%），Fleiss κ＝0.344 | 第 6.2 节，附录 E |
| 守门能力来自合成数据 | 中层披露差：只用合成 +0.610，合成加真实 +0.520，只用真实 +0.080；只用真实到只用合成差 +0.532（p＝0.0001）；在合成上再加真实，看不出改进 | 第 6.3 节，附录 D.5 |
| 守门已经学进权重 | 训练好的模型运行时拿掉门的信息，变化 −0.022（区间 −0.093～+0.053，n＝321）；同样操作对 gpt-5.3，中层披露差从 0.600 掉到 0.360，少了五分之二。前沿模型靠"现场读规则"守门，训练过的不靠 | 第 6.3 节，附录 D.5 |
| 拿掉门，排名变、分数不变 | 同一评测环境换种子重跑：排名相关 0.986、最多挪 1 位（这是噪声范围）。训练时拿掉门的信息：最多挪 3 位（噪声的 3 倍），而 12 个系统各自的分数都没有可测的变化 | 第 6.4 节，附录 D.6 表 D5 |
| 直接用提示词的前沿模型：排名像、分数虚高 | gpt-5.1 当环境，排名相关 0.972、最多挪 2 位，看排名像是合格；但 12 个系统的分数全部显著上调，平均 +0.521 分，门相关读数偏离 46%（"核心"比例最多 +93%）。只看排名的检查发现不了 | 第 6.4 节，表 D5 |
| 只有一个候选两条都过 | 两条验收标准：排名保序（相关 ≥0.95）、分数尺度不变。只有 122B 的 M1b 都过（相关 0.993，分数 0/12 变化），作为评测环境发布；35B 的 M1 相关只有 0.853、最多挪 5 位 | 第 6.4 节，表 D5 |
| 规模怎么选看用途 | 当探针，35B 够了（放大 3.5 倍对守门读数没有可测影响）；当评测环境要 122B（排名相关 0.993 对 0.853） | 第 7 节，附录 D.5 |

**能推到别的领域吗（作者的设想，没有实现和验证）**

作者把机制抽象成四个与领域无关的部件：有序的状态梯子、按对方行为类别决定的转移、不对称后退、每个样例单独编译的门说明（附录 G.1，表 G1）。并给了三个草图（附录 G.2）：

| 领域 | 梯子（由浅到深） | 怎样开门 | 怎样关门 |
|---|---|---|---|
| 面试 | 对职位的表面兴趣 → 真实离职原因 → 薪资底线和手上的 offer → 个人限制 | 问行为题而不是假设题、准确复述技术细节、先说自己团队的难处 | 对简历空档下评判，之后候选人只给标准答案 |
| 问诊 | 主诉 → 相关病史 → 羞于启齿的信息 → 从没说出口的担心 | 问开放题、把症状正常化、解释为什么要问 | 对没按时吃药说教，之后病人开始轻描淡写 |
| 谈判 | 立场 → 利益 → 约束 → 最佳替代方案（BATNA） | 问利益而不是问价格、先透露自己的一条约束 | 威胁，之后对方退回立场式讨价还价 |

作者认为这三类现有基准有同一个漏洞：奖励"问全了"（每个槽、每个症状、每个条款），而不是"让握有信息的一方愿意说"（附录 G.3）。不适用的情况：订机票、查余额这类纯任务对话（没有要赢的关系），以及信息持有方没有理由隐瞒的场景（附录 G.4）。

**需要说清楚的边界**

- 作者自己承认：审核评审能看到深度标签，所以"过早披露"的判定只是一致性检查，不是独立重建；逐轮行为标注在两个模型之间一致度只有 κ＝0.427，绝对值不能跨批次引用；主指标本身带有可测的评审效应（换评审差 −0.100）（局限一节，附录 C.4、D.5）
- 作者自己承认："核心"层的标签大多是推断的：中文评测人设里"核心"条目 88.6% 是标注模型推断出来的、没真说过，平均置信度 2.37（满分 5）。所以"核心"这一层承诺的含义比数据能支撑的强（附录 F.4 表 F3）
- 作者自己承认：门是一份规格，不是对人与人之间如何披露的描述模型。人对 AI 说话有"去抑制"效应（更容易说），方向和梯子相反，规格里没有表示；在真实对话上，预测只对了一半（顺序成立，总深度不成立）（局限一节）
- 作者自己承认：两条验收标准不是预先登记的，是在"总深度"结论被撤回之后才重新构造的；排名被挪动只说明门"承重"，不说明它有害（局限一节）
- 作者自己承认：下游证据只有英文，中文发布版 M3b 没有排名保序的直接证据；没有证据说明评审打的分和人的真实感受一致；真人研究只用中文语料，5 名评审全是项目组内部成员；"人对人"的对照组也明显分得出（0.79～0.91），所以这项研究缺一个真正处在 50% 的对照（局限一节，附录 E）
- 作者自己承认：本该给"和人设性格不符"的真实轮次降权，但这个标记没进训练样本，降权实际没生效；只做了监督微调，模拟器的单条消息变短了：53.5% 的轮次不超过 8 个汉字，真人是 27.1%（局限一节，附录 F.5）
- 作者自己承认："敷衍话"的转移规则是作者自定的，没有理论或数据依据；在低两道门上，敷衍不扣分、踩雷反而扣，和设计意图相反，是规格的缺陷，等后续版本修（附录 B.1、D.4）
- 英文语料是从中文轨迹改写来的，不是英文真人数据；真实数据来自一个未具名的线上陪伴产品，已脱敏，不公开（附录 F.6、K）
- 下游的"0.993"是和 CompanionBench 已发布排行榜对齐的程度，不是和真人对齐；作者自己说两条验收标准都不看"像不像真人"（第 7、8 节）。CompanionBench 的作者名单里也有 Liu Y. 和 Huang J.，可能是同一团队给自己的基准补规格（推断，待确认）
- 常见的误读：这篇不是说"模拟用户已经和真人分不出来"，作者明确否认了（第 6.2 节）
- 预印本，尚未同行评审；模型和代码写着"发表时公开"，目前外人无法复现

## 溯源

- 核心主张：用模拟用户评测陪伴 agent 时，用户肯说多深要由 agent 每一轮的表现来“开门”：门有先后、不能跳级、退得快建得慢；不加这道门的模拟器不问也说，评测就只奖励“问得多”，而且只看排名的验收发现不了分数虚高。
- 源知识：
  - [社会渗透理论](../roots/social-penetration-theory.md) · 关系：直接源自 · 强弱：强。作者明引 Altman 和 Taylor 1973：关系由浅入深、受损就退，五道门和三层披露深度就是把这条理论写成了状态机
  - [治疗联盟的破裂与修复](../roots/safran-2000-alliance-rupture-repair.md) · 关系：直接源自 · 强弱：强。作者明引 Safran 和 Muran 2000：评判、说教让门后退、要重新赢回来，对应治疗联盟的“破裂与修复”
