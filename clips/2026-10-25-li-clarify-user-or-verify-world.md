### 内容要点（模型概括，不是原文）

**要解决的问题**

会用工具的 agent（客服、订票这类）不光要知道"自己信息不够"，还要知道"缺的信息该找谁要"：问用户，还是自己去查系统。现有的"主动"做法大多只会其中一种（第 1 节）。

论文开头的例子（第 1 节，图 1）：用户说"把回程改成晚一点的航班"。
- 只会问用户的 agent：问清了"要 6 点后最晚的那班"，接着又问用户 13 位票号，可票号系统里就查得到，用户记不住，任务卡住
- 只会查系统的 agent：查到了订单和航班，但没问"晚一点"是什么意思，订成了 17:30，用户要的是 22:10
- 两种都会的：先问清偏好，再去系统里查有没有、差价多少，然后请用户确认

**核心想法**

1. 把"拿不准下一步做什么"拆成两种来源（第 3.2 节）：
   - 用户那边的不确定：对用户目标有几种合理理解，不同理解会导向不同的下一步。这种只能问用户（论文叫 CLARIFY，澄清）
   - 世界那边的不确定：就算目标理解对了，下一步还是定不下来，说明缺的是系统状态、规则、算出来的数这类事实。这种该自己去查（VERIFY，核实）
   - 两种都不高就直接做（ACT）
2. 怎么量：让模型独立猜 5 种用户目标，每种目标下各抽 4 个候选动作并打分。几种理解之间下一步分歧越大，用户那边的不确定越高；每种理解内部下一步越散，世界那边的不确定越高。数学上就是把下一步的总不确定拆成"互信息"和"条件熵"两块（第 3.2 节公式 3～5，附录 A.2.2）
3. 先看用户那边：用户的意思没定，查什么都可能查错方向，所以先问人，目标定了还拿不准才去查（第 3.2 节公式 6）
4. 分流只决定"找谁"，还要决定"问什么"。作者训练一个小模型（Qwen3-1.7B）专门出问题，奖励是"问完、拿到回答后，正确答案变得多好猜"：澄清时看真实用户目标是不是更好猜了，核实时看标准的下一步动作是不是更好猜了。一个模型同时学会两种问法（第 3.3 节）

**主要方法**（第 3 节，附录 A.2～A.4）

| 部件 | 做什么 |
|---|---|
| 拆解器 | 每一步调用约 30 次模型（5 种目标理解 × 每种 4 个候选动作，加打分），算出两种不确定，按两个门槛分流 |
| 门槛 | 在另外 240 个零售场景的决策点上调，这些点先由 GPT-5.5 按固定规则标好"该问人 / 该查 / 不用"，再由作者人工复核；选出的门槛是 0.25 和 0.20（第 4.1 节，附录 A.2.2） |
| 出题模型 | 澄清模式只许问用户意图，不许问工具查得到的数据；核实模式只许问可以查证的事实，不许去问用户（附录 A.4.2） |
| 核实器 | 只能用只读工具，不能改系统状态；回答必须引用工具返回值、写出计算过程或引用规则原文，做不到就回"证据不足"（第 3.3 节，附录 A.4.3） |
| 训练用的模拟用户 | 故意设得很"严"：只有问得具体、相关才透露信息，问"还有别的吗"这种泛泛的问题就回"没了"，防止出题模型靠泛问刷分（附录 A.3） |

**实验设置**（第 4 节，附录 A.2.1）

- 测试集 τ-bench：只用 500 条零售对话训练，在 115 个零售任务和 50 个航空任务上测；航空完全不参与训练和调门槛，当作没见过的领域
- 另外不重训、不重调门槛，直接拿去测 τ3-bench 的零售、航空、电信三个领域
- 除出题模型外，agent、拆解器、模拟用户、核实器都是冻结的 Qwen3-8B
- 对照方法 5 个（Ask-before-Plan、VerifiAgent、SABER、SAGE-Agent、IG-clarifier），都由作者在 Qwen3-8B 上重新实现；另有三个拆解实验：直接让模型判断该问还是该查（不算不确定）、只留澄清、只留核实
- 成功率是 3 个随机种子的平均

**主要结果**

| 结果 | 数字 | 出处 |
|---|---|---|
| 缺的信息大多在系统里 | 从 τ-bench 历史对话里标出 19,022 个"拿不准"的决策点：89.1%（16,947 个）缺的是系统那边的信息，只有 10.9%（2,075 个）真正要问用户。最多的是"找到是哪个用户、哪张订单"（6,438 个），其次是查当前状态（3,880 个）、核对工具参数（2,356 个）；另有 645 个是"问了用户其实查得到的东西" | 第 1 节，图 2；附录 A.1，表 5 |
| 成功率最高、步数最少 | 平均成功率：基础 agent 17.40%，最强的已有方法 Ask-before-Plan 23.60%，本文 28.17%（高 4.57 个百分点）；总步数：基础 28.90，Ask-before-Plan 23.50，本文 21.33（少 2.17 步） | 第 4.2 节，表 1 |

| 算不确定比直接问模型分得准 | 在 240 个航空决策点上，按不确定分流的三分类 F1 是 74.04%，直接让模型判断是 54.24% | 附录 A.2.2，图 7 |

| 门槛要跟着模型调 | 拆解器换成 GLM-4-32B 后重调门槛（0.20 和 0.08），平均成功率从沿用旧门槛的 33.26% 升到 37.00%，但介入步数也变多 | 附录 A.2.2，表 6、表 7 |
| 不是每一步都要分流 | 每场最多调用拆解器 16 次时最好（29.42%）；不限次数是 28.17%、每场约 697 秒；只调 1 次是 18.37%。改成每 2 步调一次，成功率差不多（27.32%）但总步数反而变多（25.26）；每 8 步一次掉到 19.55% | 第 4.4 节，图 5；附录 A.2.3，表 8 |

**需要说清楚的边界**

- 绝对成功率很低：最好的设置也只有 28% 左右，因为主实验用的是很小的 Qwen3-8B；换更强的 agent 后能到 48%
- "九成缺的是系统信息"这个数，来自 GPT-5.5 对历史对话的标注加作者人工复核；附录里的例子编号显示这些历史对话是 gpt-4o 跑出来的，所以这个比例反映的是那批 agent 的表现，换别的 agent 比例可能不同；而且数的是决策点，不是任务数，一个任务可以算好几次（附录 A.1）
- 作者自己说明，这里的"用户那边 / 世界那边"是好用的操作标签，不是严格的贝叶斯意义上的两种不确定（第 2 节）
- 核实的训练目标是参考对话里的"下一步动作"，作者承认这不一定是唯一正确的动作（第 3.3 节）
- 用户全部由模型模拟，没有真人用户测试；训练时的模拟用户比测试时更"严"
- 门槛和模型绑定，换模型要重新调（附录 A.2.2）
- 成本不低：每个决策点约 30 次模型调用，每场约 700 秒；论文没报基础 agent 的耗时，没法直接比"多花了多少"（附录 A.2.2、A.2.3）
- 不是每一格都赢：未训练的 DeepSeek-V4-Flash 出题略好于训练过的小模型；τ3-bench 航空上直接让模型判断的做法是 36.00%，高于本文的 30.00%；agent 换成 Qwen3-32B 时，航空上未训练的出题模型 46.00% 也高于本文的 44.00%（表 2、表 3、表 4）
- 只测了文字类的交易型客服场景，银行和语音领域不在当前动作范围内（第 4.3 节）
- 对照方法都是作者自己在 Qwen3-8B 上重新实现的，不是原作者的版本
- 作者声明用 AI 协助起草和修改论文、标注不确定类型和调门槛用的数据，所有标注都经过人工复核（AI 使用声明一节）
- 正文说测的是 τ3-bench，参考文献里对应的条目标题写的是 τ2-Bench（Barres 等 2026），两处名字不一致，照论文写

## 溯源

- 核心主张：agent 拿不准下一步时，要先分清缺的信息该找谁：对用户目标有几种合理理解、各自导向不同动作时问用户（澄清），目标定了下一步仍定不下来时自己用工具查系统（核实），两种都不高就直接做；把下一步的不确定拆成“不同目标理解之间的分歧（互信息）”和“每种理解内部的散度（条件熵）”来分流，先澄清后核实，再训一个小模型按信息增益出问题。τ-bench 历史记录里约九成拿不准的决策点缺的是系统里查得到的信息，按来源分流后成功率比最强对照高 4.57 个百分点、步数少 2.17 步。
- 源知识：
  - [BALD：按分歧做贝叶斯主动学习](../roots/houlsby-2011-bald.md) · 关系：直接源自 · 强弱：强。论文把下一步的总不确定拆成“不同用户目标理解之间的分歧（互信息）”加“每种理解内部剩下的熵（条件熵）”，这正是 BALD 的分解（总预测熵 = 参数假设之间的分歧 + 每个假设下的期望熵），只是把“模型参数”换成了“用户目标的几种理解”；论文明引 Houlsby 等 2011。
  - [偶然不确定性与认知不确定性](../roots/der-kiureghian-2009-aleatory-epistemic.md) · 关系：相近 · 强弱：强。论文明引偶然不确定和认知不确定的拆分（Kendall 与 Gal 2017），“用户那边 / 世界那边”是同一种“先分清不确定从哪来、再决定怎么应对”的思路；作者自己说这是好用的操作标签，不是严格的贝叶斯拆分。
  - [信息价值理论](../roots/howard-1966-information-value-theory.md) · 关系：相近 · 强弱：弱（模型复核通过）。问用户、查系统都有成本，只有能改变下一步决定的信息才值得要；论文引了用“完全信息的期望价值”给澄清问题排序的 Rao 与 Daumé III 2018，出题模型的奖励也是信息增益。没直接引 Howard，是模型推断。
  - [混合主导用户界面的原则](../roots/horvitz-1999-mixed-initiative-user-interfaces.md) · 关系：相近 · 强弱：弱（模型复核通过）。Horvitz 的混合主导原则里就有“考虑对用户目标的不确定”“按期望价值决定何时行动”“拿不准时用对话澄清”，和“先澄清用户目标、再行动”几乎同构。论文没引，是模型推断。
- 本质：这条新知识本质上是贝叶斯主动学习里“总不确定 = 假设之间的分歧 + 假设内部的随机”这一信息论分解，在客服类 agent 决定“问用户还是查系统”上的应用。
