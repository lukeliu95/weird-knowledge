## 使うツール

- Opus 5.5 (Claude Code)
- MiniMax H3 FL2V
- Blender 5.x
- 三面図を作れる画像生成AI（GPT image など）
- Tripo3d (Multiview to 3D)

LLM はいろいろ試しましたが、2026/10 現在は Opus 5.5 が一番上手に（かつトークン少なく）できるようです。Astra 6 / Sol 6.1 で作ると、若干カクカクした動きになる気がしました。

動画生成 AI は MiniMax H3 でなくてもいいです。ただ、H3 はキャラクタの一貫性が保たれやすい、生成コストが低い、ローカルでも生成可能と、いろいろ利点があるのでお勧めです。

Blender は必須です。冒頭の動画のモーション作成には 5.2 LTS を使っています。

三面図は人物なら「正面、側面、背面」、四足動物や鳥なら「正面、側面、上面」を作ります。

3D モデル化については、冒頭の動画のモデルでは Tripo3d を使いました。他のツールでもいいかもしれませんが試してはいません。

## 手順

- GPT image などでキャラクタの三面図を作る
- Tripo3d (Multiview to 3d)で3D化する
- MiniMax H3 FL2V でモーション（歩行、飛行など）を作成する
- Opus 5.5 (claude code) に3dモデルと動画を与えてモーションを作成させる

API 経由で GPT Image  や Tripo3d を駆動すれば Opus 5.5 に上記の作業を全部自動でさせることも多分可能です。

以下、各手順の内容について順番に説明します。

## 三面図を作る

GPT Image の場合、作りたいキャラの画像を何枚か与えて「このキャラクタの三面図（正面、側面、背面）をそれぞれ1枚の画像で作ってください」とか言えば作ってくれます。nano banana などの他の画像生成AIでもできると思います。

## 3Dモデルを作る

Tripo3d などで3Dモデル化します。下の図は fal.ai を使って作成したときの様子を示しています。

![](https://assets.st-note.com/img/1791790504-xAVM5O3Lfwqb6nKh9p7zdZy2.jpg)

３Dモデルの作成

1枚絵で作るより Multiview to 3d で正面、側面、背面（または上面）と複数の画像を入れたほうが出来上がりのモデルの精度が高まります。

ポリゴン数は、多くするとモデルが複雑になって、動かした時に不整合が出やすい気がします。これまで試した感じでは、人体のモデルなら 2万～20万くらいの範囲がよさそうです。

上のモデルでは人体＋羽根がついてるので、4万と少し多めに設定してます。

## モーションの動画を作る

MiniMax H3 などでモーションの動画をFL2V で作ります。**ポイントは「正面・側面」の最低でも二種類の方向からの動画を作る**ことです。

下の動画は first frame の画像を1枚与えて「正面に向かって5秒間歩き、そのあと左に向かって5秒間歩く」というプロンプトで作成しました。

（嵌入：https://youtube.com/shorts/SjKW2oh66hI?feature=share）

バラバラに二本作作るのではなく、**1本の動画の中で角度をかえて動かす**と、歩くタイミングやリズムが揃いやすいです。

音楽を入れると、**音楽にあわせて歩調が合う**ため、正面と側面の両方での歩調のタイミングがさらに合いやすくなります（何も指示しなくても MiniMax H3 だと音楽は勝手に入ることが多いです）。

1枚絵を作る時は、キャラクタシートのものをいれるのではなく、**3Dモデルを blender に読み込ませて白背景で正面からレンダリングした画像**を入れます。

Opus 5.5 に上記のような画像を作ってほしいといえば作ってくれるので、それを動画の first frame として入力すればOKです。

キャラシートの画像をそのまま入れると、3D 化されたモデルと微妙に違っていて、Opus 5.5 が動画とモデルを比較するときに、うまくいかないことがあります。アニメ風のモデルなら**「トゥーンぽくレンダリングして」**とプロンプトに加えると、元画像の見た目に近づいて一致度が高まります。

動画の解像度はそこまで高い必要はありません。作成したいモーションにも依存すると思いますが、歩行とか飛行くらいであれば解像度は 480p とかで問題ないです。

## Opus 5.5 でリギングとモーション作成をする

作成した 3d モデル、動画を Opus 5.5 (claude code 上で）渡して下記のような感じのプロンプトで作業させます。

```
動画には正面と側面から撮影した歩行モーションが収録されています。3Dモデルと動画を解析して、3D モデルが動画の通りに動くようにリギングと歩行のモーションの作成をしてください。歩行モーションはループモーションになるようにしてください。
```

Opus 5.5 が動画を分析して、分析結果と質問を表示してくる（多分）ので、それに答えてモーションの作成を実施させます。

一例ですが、冒頭の動画のモーションを作成したときは、Opus 5.5 は下記のようなレポートと、作成にあたっての質問事項（決めてほしいこと）を提示してきました。

![](https://assets.st-note.com/img/1791792565-JytfNT641BCjbcgonlHWrR2P.png)

Opus 5.5 の動画解析結果レポートと質問事項

上の例では、人間の回答として「ループは 30 フレームでOK、正面の映像を優先でOK、尻尾は短いままでOK」と答えました。

この条件で、歩行モーション（ループ）を作成した結果が下の動画です。左は MiniMax H3 が作成した元映像（参照動画）で、右が Opus 5.5 で作成したモーションを blender でレンダリングして作成した映像です。

作業時間は 10 分程度でした。

（嵌入：https://youtu.be/pDVRGmdnYPY）

修正なしの1回目作成のモーション作成でこのクオリティは結構すごくないですか？

同じ要領で飛行モーションなども作ることができます。

モーションを何種類か作ると、Opus 5.5 がリグを作り直したり微修正したりすることがあります。ある程度モーションを作ったら、修正された（より詳細化された）リグで、全部のモーションを作りなおします。

こうしておくことで、すべてのモーションで同じリグをつかうことができるようになります。

この方法を使えば、人間ではない動物や魔獣などのモーションも、比較的簡単に作ることができます。

（嵌入：https://x.com/IsekaiBardGuild/status/2108973710665519305）
