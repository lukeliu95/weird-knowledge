### 内容要点（模型概括，不是原文）

**要解决的问题**

agent 的本事很大程度上由 harness（模型外面那一圈：提示词、控制流程、工具、记忆、上下文管理）决定。现在很多方法让模型自己反复提改动、在一套固定的题（"进化集"）上打分、留下分高的，等于在 agent 系统这一层做"递归自我改进"（RSI）。问题是同一套题被一轮轮反复用，harness 会"背题"：在进化集上涨很多，换一套题就涨得很少甚至倒退（第 1 节，图 1a）。

作者把"背题"拆成三种互相纠缠的行为：写进只对这套题有用的东西（针对题库的拟合）、把运气好的一次高分当真（追噪声）、越堆越复杂却没改进 agent 真正的做事机制（复杂度累积）（第 1 节）。

**核心想法**

改动范围不设限（提示词、流程、配置、上下文、工具、skill、记忆、子 agent 都能改、能加、能删），改为约束"搜索怎么走"。把机器学习里防过拟合的正则化思路翻译成 harness 搜索的规矩，分"提候选"和"选候选"两边（第 3、3.1 节，图 2）。作者反复强调这只是"功能上的类比"，不是真的在优化 L0/L1/L2 范数（第 3.1 节，附录 D）。

**主要方法**

| 哪一边 | 规矩 | 做什么 | 类比 |
|---|---|---|---|
| 提候选 | 改动预算逐轮收紧 | 一个候选里能打包几处独立改动有上限，按余弦曲线从 3～4 处降到 1 处：早期可以几处一起改去找新机制，后期每次只改一处，方便看清是哪处起作用（第 3.2 节公式 4，附录表 5） | L0（限制非零个数） |
| 提候选 | 记住全部试错 | 每次试过的改动都记下：改了哪个部件、想验证什么假设、代码差异、分数和花费变化、有没有被采用。下一轮提议时带上，已被否定的假设不再重试（第 3.2 节，附录 D.2） | 引 Dwork 等 2015 "反复用同一份留出集会过拟合" |
| 提候选 | 卡住了就换方向 | 连续 3 轮进步都在噪声范围内，就留一个候选名额专门去改还没碰过的部件（比如一直在改提示词，就去试工具、记忆、子 agent）（第 3.2 节，附录 D.2） | 多样性 / 熵正则 |
| 选候选 | 先筛泄题 | 打分之前，由一个"审查模型"读代码差异，拒掉写了题目名、实体名、具体数值、答案或只对这套题有用的逻辑，以及加了不起作用的空架子的改动。只看代码差异，不看提议理由：理由里可以提到想修哪道题，但这些内容不能进代码（第 3.3 节，附录 F） | — |
| 选候选 | 涨分要超过噪声 | 先把原始 harness 反复跑几次，量出"同一个 harness 两次跑分能差多少"（噪声带 δ）。候选分数不能低于历史最好分减 δ，防止一步步小幅倒退被当成噪声放过（第 3.3 节公式 5） | — |
| 选候选 | 多花要用涨分换 | 涨分超过噪声时，token 花费的增幅不能超过"基础额度＋系数×涨分"；涨分在噪声以内时，只有省了 token 或用上了从没被采用过的结构部件（工具、skill、记忆、子 agent）才算数，在编程场景里单靠噪声内的涨分进不来（第 3.3 节公式 7，附录 D.3 公式 17） | L2（压总体规模） |
| 选候选 | 没用就删 | 最近几轮（4～5 轮）里一直没带来正收益的部件，列给提议模型当删除目标（第 3.3 节，附录 D.2 公式 14） | L1（让结构变稀疏） |

每轮出 2 个候选，各在自己的 git worktree 里改、筛、评，采用就把分支快进过去，所以"当前冠军"永远是一次提交（README）。实验里被冻结的执行模型、提议模型、写失败分析的模型和审查模型都是 Claude Opus 4.8（第 4.1 节）。

**主要结果**

在 3 个领域、8 个测试集上测：每个领域只在一套题上进化，然后原样拿去跑没见过的题。所有数字都和同一时段重测的原始 harness（H0）比（第 4.2 节，图 3）。

**需要说清楚的边界**

- 只改 harness、模型权重不动；进化过程里会改权重的情况没研究（第 6 节「局限」，附录 A）
- 仍然依赖一套有限的进化题和好几个超参数，效果取决于反馈信号的质量和搜索预算；换成很不一样的 agent 架构、工具生态、跑得更久的自我改进，还要更多验证（附录 A）
- 涨分的绝对值不大：没见过的题上是 +1.8～+4.7 分；在进化集上它反而是涨得最少的（第 4.2 节）
- "L0 / L1 / L2"只是打比方，作者多次声明不是在优化对应的范数目标（第 3.1、3.2 节，附录 D）
- 超参数（噪声带、预算、花费系数）在进化集上定、事后不调，作者说没看留出集和没见过的题（附录 E.1）；但花费系数是"让开头几轮里最好的那个候选正好能进"来校准的（附录 E.1）
- 办公类测试集多数由模型打分（Gemini 3.5 Flash，GDPval 用三家模型投票），作者用确定性打分的工程设计类来排除"讨好打分模型"的可能（第 4.2 节，附录 B）
- Frontier-Eng 的 47 题里只有 38 题在他们的环境里跑得起来，两边都按同一批题算（附录 B.8）
- 对比的 4 种方法是作者在同一设置下复现的，不是原作者跑的（第 4.1 节，附录 C）

## 溯源

- 核心主张：让 agent 在同一套题上反复改自己的运行框架（harness）会“背题”：写进只对这套题有用的东西、把运气好的一次高分当进步、越堆越复杂；把机器学习的正则化翻译成搜索规矩（改动预算逐轮收紧、记住全部试错、打分前筛掉泄题改动、涨分须超过实测噪声带、多花的 token 要用涨分换、没用的部件删掉）后，进化集上涨得最少，换成没见过的题反而涨得最多，且比不加正则化的进化少用约 30% 执行 token（但仍比原始框架贵）。
- 源知识：
  - [递归自我改进](../roots/recursive-self-improvement.md) · 关系：直接源自 · 强弱：强。摘要明说自动提改动、选改动的 harness 进化“实际上就是 agent 系统层面的递归自我改进（RSI）”，RRSI 是给这种 RSI 加约束，防止它在进化集上过拟合。
  - [正则化（防过拟合的约束与惩罚）](../roots/regularization.md) · 关系：直接源自 · 强弱：强。论文把机器学习防过拟合的正则化原则搬进 harness 搜索：限制一个候选打包几处改动对应 L0，删掉一直没用的部件对应 L1，压 token 花费对应 L2，并引 Goodfellow 等 2016、Hastie 等 2009；作者反复声明这只是功能上的类比，不是真在优化范数。
  - [可复用的留出集（自适应数据分析中的泛化与留出集复用）](../roots/dwork-2015-reusable-holdout.md) · 关系：直接源自 · 强弱：强。“记住全部试错”一条明引 Dwork 等 2015（NeurIPS 版《自适应数据分析的泛化与留出集复用》）：同一份题被一轮轮拿来挑候选，题本身就会被过拟合。RRSI 的“涨分要超过实测噪声带才算”和 Dwork 等的 Thresholdout（训练与留出结果差距超过加噪门槛才报留出集的值）是同一思路，这半句是模型推断。
  - [古德哈特定律](../roots/goodharts-law.md) · 关系：相近 · 强弱：弱（模型复核通过）。进化集分数一旦成了要优化的目标，就不再代表 agent 的真本事：对照方法在进化集上分最高、换题后不涨甚至倒退，留下的是复述这套题评分方式的“迎合打分”规则。论文没提古德哈特定律，是模型推断。
  - [雷曼软件演化定律](../roots/lehmans-laws-of-software-evolution.md) · 关系：相近 · 强弱：弱（模型复核通过）。论文说的第三种背题“复杂度累积”（越堆越复杂却没改进做事机制，如对照方法留下约 8,500 字的协议），和雷曼第二定律“演化中的系统复杂度会上升，除非专门投入去降”一致；RRSI 的“没用就删”就是那份专门投入。论文没引雷曼，是模型推断。
- 本质：这条新知识本质上是机器学习防过拟合的正则化思想（少改、惩罚复杂度、涨分要超过噪声、留出集不被反复榨干）在 agent 运行框架递归自我改进上的应用。
- 整理于：2026-10-25（第 8 轮）
